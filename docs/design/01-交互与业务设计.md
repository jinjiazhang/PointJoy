# 积乐圈 · PointJoy：交互与业务设计 v0.1

设计日期：2026-09-14。状态：开发前设计，未实现或部署。配套文档：[接口协议](02-接口协议.md)、[数据存储与一致性](03-数据存储与一致性.md)。

## 1. 第一版产品边界

技术基线：uni-app / Vue 3 / TypeScript 小程序，NestJS 服务端，PostgreSQL，Prisma 管理模型与迁移，COS 保存图片。网页运营后台后续使用 Vue 3 / Element Plus，复用服务端领域逻辑。

以下是为形成完整方案采用的产品默认值，可以在开发前调整：

- 微信小程序优先。每个成员绑定一个已登录用户；管理员通过邀请添加成员。本期不引入儿童档案或监护关系。
- 已确认：一个用户可以创建多个群、加入多个群，并切换操作。创建群会自动建立群主成员关系，因此创建的群也在“我的群组”中。角色按群独立，同一用户可在 A 群是群主、B 群是管理员、C 群是成员。
- 积分按群独立，不跨群流通、不转账、不购买、不提现、默认不过期；可用余额不得为负。
- 群主、管理员也有积分账户，但不能给自己发分或调整自己的积分。第一位群主可邀请其他管理员后由他人操作。
- 成员通过邀请申请入群，由管理员审核；没有公开群搜索。邀请码过期或撤销不影响已提交申请，审核仍检查群有效性。
- 管理员对他人发分或调整积分，必须填写原因。每次只操作一个成员，批量发分留待后续。
- 一次兑换一种奖励的一份，先不做购物车、多件数量、兑换审批和混合支付。
- 虚拟奖励指“免一次家务、游戏时间、优先选择权”等群内权益；通过管理员核销交付。实物奖励第一版线下领取。自动发券、第三方数字商品和快递发货作为后续扩展。
- 兑换成功立即扣分和占用库存，订单进入待领取；成员可在核销前取消，管理员可因无法提供奖励取消。取消全额返分并恢复库存。
- 第一版无排行榜，普通成员不能查看他人的余额或流水。
- 第一版不开放退出、移除成员、删除或解散群组，避免未结订单与历史资产归属不明确；数据不硬删除。后续必须先定义资产及订单结清规则。

## 2. 信息架构

固定底部导航：**群组 / 奖励 / 我的**。当前群组名称始终显示在群组和奖励页顶部，点击切换；群组上下文不跨用户保存。

| 页面 | 普通成员看到的内容 | 管理员额外入口 |
|---|---|---|
| 群组首页 | 当前群、我的积分、最近流水、群简介 | 发积分、成员管理、待加入、待核销、群设置 |
| 群组切换 | 已加入群列表、创建群、填写邀请码 | 无 |
| 奖励列表 | 当前群已上架奖励、价格、可兑换状态 | 管理奖励 |
| 奖励详情 | 图片、说明、积分价格、库存状态、领取方式 | 编辑、上下架、调整库存 |
| 我的 | 个人资料、当前群积分明细、我的兑换、切换群组 | 无 |
| 兑换详情 | 奖励快照、状态、扣分、核销码、取消入口 | 核销、取消订单 |
| 管理面板 | 不显示 | 成员、申请、奖励、订单、操作记录 |

管理员不切换独立“管理员登录”。服务端返回当前群 capabilities，前端据此展示入口；所有接口仍检查实时权限。

### 多群切换规则

- 群组选择页统一列出本人创建和加入的群，每行显示群头像、群名、当前角色和本群积分；可从列表继续创建群或输入邀请。
- 点击群组进入该群首页，刷新成员身份、权限、积分、奖励和管理待办。页面顶部持续显示当前群名，管理确认框再次显示群名和目标成员。
- 本地按 userId 保存 lastActiveGroupId；再次打开时先校验访问权，失效则进入群组选择页。首次登录有多个群且没有最近选择时，由用户选择。
- 切换时退出旧群详情路由，进入目标群首页；未提交表单提示放弃或留在当前页。写请求进行中先等待结果；结果未知时保留原幂等键确认，解决后再切换。
- 所有请求绑定发起时的 groupId，切换不改变已发出请求归属。缓存键包含 userId + groupId，使用切换序号丢弃晚到响应。
- 分享进入指定群时，已入群则切到目标群；未入群则进入申请流程。待审批申请不替换当前可操作群。
- 当前群是客户端导航状态，不是服务端会话的全局字段；不同设备可以同时操作不同群。

## 3. 核心交互流程

### 3.1 首次进入、创建群

1. 展示产品介绍，点击“开始使用”发起微信登录；头像、昵称另行编辑，不把资料授权当作登录前置条件。
2. 没有群组时显示“创建群组”和“输入邀请码”；有待审批申请时显示申请状态。
3. 创建页填写群名（2–30 字）、简介（最多 200 字）；头像可选。
4. 提交成功后创建群、群主成员和零余额账户，直接进入群首页。重复提交只创建一个群。
5. 创建成功提供“邀请成员”入口；取消邀请面板不影响创建结果。

### 3.2 邀请与审批

1. 群主/管理员生成邀请链接或复制邀请码；默认有效 7 天、最多接受 100 个不同用户申请，可撤销。
2. 受邀人进入邀请预览，只显示群名、简介和头像；登录后点击申请加入。
3. 待审批页显示“已提交，等待管理员审核”，允许撤回申请；重复申请复用同一待审批记录，不重复占名额。
4. 管理员查看申请人昵称和申请时间，点击同意或拒绝；拒绝原因选填，最多 200 字。
5. 同意后原子创建成员及零余额账户。申请人重新进入或下拉刷新时进入群；第一版不依赖订阅消息。
6. 已入群用户再次点击邀请直接打开该群。拒绝/撤回后可通过仍有效的邀请重新申请。

### 3.3 发积分、调整与冲正

1. 管理工具 → 选择成员（不能选自己）→ 输入正整数和原因 → 确认。
2. 确认框明确显示“给 张三 增加 10 积分”，提交中禁用重复点击。
3. 成功页显示流水编号、变动数、变动后余额；刷新相关页面。
4. “调整积分”独立入口，支持增加或减少，减少时明确提示将扣分；不允许直接输入最终余额。
5. 发错分时从原流水进入“冲正”，显示原记录及相反变动。一次只能完整冲正一次，不允许冲正兑换流水或冲正流水。
6. 正向发分已被使用、冲正后余额不足时阻止冲正；管理员可走有原因的新调整，但不能产生负余额。

### 3.4 奖励管理

1. 管理奖励 → 新建 → 填写名称（1–50 字）、描述（最多 2000 字）、图片、类型、正整数积分价格、初始库存。
2. 类型为 VIRTUAL（群内权益）或 PHYSICAL（线下实物），都使用有限非负库存；尚不提供无限库存。
3. 默认保存为草稿。管理员确认领取说明后上架；库存为 0 可以上架但成员端显示“已兑完”。
4. 上架后可改文案和价格；库存通过“增加/减少库存”独立操作，填写原因。奖励类型创建后不可改。
5. 下架只阻止新兑换，不取消已有订单。已有兑换保存名称、图片、价格和领取说明快照。

### 3.5 兑换与领取

1. 奖励详情同时显示“需要 50 积分 / 我的积分 120 / 线下领取”。余额不足、已兑完或已下架时展示原因。
2. 点击兑换，确认面板再次显示群名、奖励、消耗积分和领取方式。
3. 成功后进入订单详情，显示“待领取”、积分扣减、领取说明和核销码入口。
4. 商品价格或详情版本变化时，服务端拒绝旧确认，前端刷新并要求重新确认；不能静默扣除新价格。
5. 成员出示短时核销码，管理员在本群扫描或输入；先显示订单和领取人，确认实际交付后点击“确认核销”。管理员不能核销自己的订单。
6. 核销成功进入已完成；虚拟奖励意味着对应权益已提供，实物意味着已交给成员。
7. 没有扫码条件时，管理员从待领取订单查找并确认核销，填写交付备注；服务端记录核销方式。

### 3.6 取消与竞争处理

- 待领取：成员或管理员可取消，必须填写原因；确认框显示将退还积分。
- 已完成：不提供取消或退款入口；需要业务补偿时走独立积分调整并说明原因。
- 已取消：只读。重复取消返回当前已取消结果，不再次退款。
- 核销和取消同时发生：先成功取得订单锁并提交的一方有效；另一方刷新状态并显示“订单状态已变化”。

### 3.7 管理员及群主管理

- 只有群主能授予/撤销管理员；管理员不能修改其他人的角色。
- 群主可转让给本群其他成员；确认框显示接任人，原群主转为管理员。
- 群主身份由 groups.owner_member_id 唯一表示，不额外保存可能冲突的 OWNER 成员角色。
- 角色变化不修改积分，权限即时生效；客户端缓存角色不能作为授权凭据。

## 4. 权限矩阵

| 操作 | 成员 | 管理员 | 群主 |
|---|---|---|---|
| 查看自己的积分和订单 | 是 | 是 | 是 |
| 查看已上架奖励、自己兑换 | 是 | 是 | 是 |
| 取消自己的待领取订单 | 是 | 是 | 是 |
| 查看成员列表、他人余额/流水 | 否 | 是 | 是 |
| 邀请、处理加入申请 | 否 | 是 | 是 |
| 给他人发分/调整/冲正 | 否 | 是 | 是 |
| 管理奖励和库存 | 否 | 是 | 是 |
| 查看全部订单、取消待领取订单 | 否 | 是 | 是 |
| 核销他人的待领取订单 | 否 | 是 | 是 |
| 改群简介及头像 | 否 | 是 | 是 |
| 授予管理员、转让群主 | 否 | 否 | 是 |

对当前用户没有访问权的群内资源返回 404；对已可访问群中无权执行的动作返回 403。平台运营人员不自动拥有发分或核销权限，后续另建平台权限体系。

## 5. 页面公共状态

- 初次加载显示骨架；列表为空时说明原因并提供下一步入口。
- 切换群组时取消旧请求，清空旧群数据。请求响应带群标识，晚到响应不得覆盖新群页面。
- 网络失败保留表单；写请求结果不确定时保留同一 Idempotency-Key 重试，不能显示“操作失败”后让用户重新下单。
- 登录过期先尝试刷新会话，成功后用同一幂等键重试一次；刷新失败跳转登录，保留未提交表单。
- 401、403、404、409、429 分别展示登录失效、无权限、资源不可用、数据已变化、操作过快。
- 管理表单多人同时编辑遇到版本冲突时，展示最新内容并让用户重新确认，不覆盖他人修改。
- 积分、订单状态只在服务端确认后更新；前端不乐观扣分。

## 6. 实现验收场景

1. 同一用户在 A、B 两群积分分别为 100、0，切换后不得串账或展示旧余额。
2. 普通成员修改请求中的 memberId，不能查询他人流水或给自己发分。
3. 同一兑换连续提交三次，只出现一笔订单和一次扣分。
4. 两人同时兑换最后一件奖励，只一人成功；另一人余额不变。
5. 账户 50 分，同时兑换两份各 40 分奖励，只一笔成功。
6. 扣分后数据库写订单失败，余额、库存和流水全部回滚。
7. 取消和核销并发，只出现已取消或已完成一种最终状态。
8. 管理员降权与发分并发，以受锁保护的事务顺序确定权限；降权提交后新发分被拒绝。
9. 上架奖励改价，旧确认页面收到冲突，重新确认前不扣分。
10. 下架后旧订单仍能领取或取消；取消仍恢复库存。
11. 群主转让失败不会留下无群主或双群主；原群主成功转让后成为管理员。
12. 重复冲正、重复取消、重复审批不会重复产生积分或成员。
13. 同一用户创建两个群，两群均出现在列表，分别具有群主身份和独立零余额账户。
14. 从群主身份的 A 群切到普通成员身份的 B 群，管理入口消失，直接调用管理接口也被拒绝。
15. A 群晚到响应不会覆盖 B 群页面；重新切回 A 群也须校验新的切换序号。
16. 两台设备分别操作不同群，任一端切群不影响另一端。
