# 积乐圈 · PointJoy：HTTP API 协议 v0.1

状态：接口设计，尚未实现；本文是字段和行为契约，开发时据此生成 OpenAPI 文件。配套：[交互设计](01-交互与业务设计.md)、[存储设计](03-数据存储与一致性.md)。

## 1. 通用约定

- 根路径 `/api/v1`，HTTPS，JSON，UTF-8；字段 camelCase，枚举大写。
- ID 使用 UUID 字符串；积分、库存、版本使用 JSON 整数。接口整数绝对值不超过 2,000,000,000，单次人工积分调整绝对值不超过 1,000,000。业务中间计算必须检查溢出。
- 时间为 UTC ISO 8601，例如 `2026-09-14T08:00:00.000Z`，客户端按本地时区展示。
- 认证头 `Authorization: Bearer <accessToken>`；用户身份只能从服务端会话解析，禁止接受客户端传入的 actorId、openid 或角色。
- 所有已认证 POST/PATCH 变更接口均要求 `Idempotency-Key: <UUID>`；例外：登录、刷新会话、核销预览使用专门逻辑。读接口无副作用。
- PATCH 必须携带 expectedVersion；未传字段不变，nullable 字段显式 null 表示清空；禁止未知字段。
- 默认列表 `limit=20`，范围 1–100；使用不透明 cursor，按 `(createdAt DESC, id DESC)` 游标分页。cursor 绑定群、筛选和排序条件，条件变更应重新分页。
- 成功 GET/PATCH 返回 200，创建新资源返回 201，动作返回 200；幂等重放返回原 HTTP 状态和原响应，并附 `Idempotency-Replayed: true`。
- 成员权限、群隔离、状态检查必须在服务端执行，路径 groupId 不能只用于页面展示。

成功响应：
```json
{"data":{"id":"UUID"},"requestId":"UUID"}
```
列表响应：
```json
{"data":{"items":[],"nextCursor":null,"hasMore":false},"requestId":"UUID"}
```
失败响应：
```json
{"error":{"code":"INSUFFICIENT_POINTS","message":"当前积分不足","details":{"required":50,"available":30}},"requestId":"UUID"}
```

requestId 标识一次 HTTP 调用；重放业务响应时生成新的 requestId。内部堆栈、SQL 和第三方密钥不能进入响应。下文返回类型均指 data 字段。

## 2. 登录和会话

| 方法与路径 | 请求 | 返回/语义 |
|---|---|---|
| POST `/auth/wechat/login` | `{code: string}` | `{accessToken, expiresIn: 900, refreshToken, user: User}` |
| POST `/auth/refresh` | `{refreshToken: string}` | 新 accessToken、expiresIn、轮换后的 refreshToken |
| POST `/auth/logout` | 无 | `{loggedOut: true}`，撤销当前会话 |
| GET `/me` | 无 | User |
| PATCH `/me` | `{displayName?: string, avatarAssetId?: UUID|null, expectedVersion: int}` | User |

服务端使用微信登录 code 换取身份，AppSecret 和 session_key 仅保留服务端。openid 绑定 `(provider, appId, subject)`，不通过昵称匹配账号。微信官方登录文档本次抓取失败，实现阶段需在微信开发者工具中核验登录及资料填写流程。

accessToken 采用短期签名令牌，只含 sub、sid、iat、exp 等身份信息；不携带可长期信任的群角色。请求还需验证 sid 未被撤销。refreshToken 为至少 256 位随机值，服务端存哈希，有效期 30 天。刷新需串行化并轮换，旧 token 重用撤销会话；客户端采用单次刷新合并机制。若刷新响应丢失且旧 token 无法恢复，重新微信登录，不无限重试旧 refreshToken。

## 3. 基础返回对象

- User：`id, displayName, avatarUrl|null, version, createdAt`。
- Membership：`id, groupId, userId, displayName, avatarUrl|null, effectiveRole: OWNER|ADMIN|MEMBER, version, joinedAt`。管理成员详情额外包含 account；普通响应不泄露 openid。
- Group：`id, name, description, avatarUrl|null, ownerMemberId, version, createdAt`。
- GroupContext：`group: Group, membership: Membership, capabilities: string[], account: Account, pendingApplicationCount?: int, pendingRedemptionCount?: int`。待办计数仅管理者返回。
- Account：`memberId, groupId, balance, version, updatedAt`。
- LedgerEntry：`id, groupId, memberId, type, delta, balanceAfter, accountVersion, reason, operator: {memberId, displayName}, relatedOrderId|null, reversalOfId|null, createdAt`。
- Reward：`id, groupId, name, description, imageUrl|null, type: VIRTUAL|PHYSICAL, fulfillmentMode: MANUAL, fulfillmentInstructions, costPoints, stockAvailable, status: DRAFT|ACTIVE|INACTIVE, version, stockVersion, createdAt, updatedAt`。
- Redemption：`id, groupId, memberId, rewardId, status: PENDING|FULFILLED|CANCELED, costPoints, rewardSnapshot: {name, imageUrl|null, type, fulfillmentMode, fulfillmentInstructions}, createdAt, fulfilledAt|null, canceledAt|null, cancelReason|null, version`。核销秘密不在列表/详情返回。
- Application：`id, groupId, applicant: {userId, displayName, avatarUrl|null}, status: PENDING|APPROVED|REJECTED|WITHDRAWN, decisionReason|null, createdAt, decidedAt|null`。
- Invitation：`id, groupId, expiresAt, maxUses, uses, revokedAt|null, createdAt`。明文 token/code 仅创建接口返回。
- AuditEntry：`id, groupId, operatorMemberId, action, targetType, targetId, reason|null, createdAt`；管理端不返回完整凭据或敏感原始请求。

## 4. 群组、成员和邀请

| 方法与路径 | 权限 | 请求 / 返回 |
|---|---|---|
| GET `/groups` | 登录 | GroupContext 的分页列表，包含本人创建和通过邀请加入的全部群 |
| POST `/groups` | 登录 | `{name, description?, avatarAssetId?}` → GroupContext |
| GET `/groups/{g}` | 本群成员 | GroupContext |
| PATCH `/groups/{g}` | 管理者 | `{name?, description?, avatarAssetId?, expectedVersion}` → Group |
| GET `/groups/{g}/members` | 管理者 | `query?, cursor?, limit?` → Membership 分页列表 |
| GET `/groups/{g}/members/{m}` | 管理者或本人 | Membership + account |
| PATCH `/groups/{g}/members/{m}/role` | 群主 | `{role: ADMIN|MEMBER, expectedVersion}` → Membership + version；不能修改当前群主 |
| POST `/groups/{g}/ownership-transfer` | 群主 | `{newOwnerMemberId, expectedVersion}` → Group；旧群主设为 ADMIN |
| POST `/groups/{g}/invitations` | 管理者 | `{expiresInDays?: 1..7, maxUses?: 1..100}` → `{invitation, token, code}` |
| GET `/groups/{g}/invitations` | 管理者 | Invitation 分页列表 |
| POST `/groups/{g}/invitations/{i}/revoke` | 管理者 | 无 → Invitation |
| POST `/invitations/preview` | 登录 | `{token?: string, code?: string}` 二选一 → `{group: {id,name,description,avatarUrl}, expiresAt, membershipState}`；逻辑只读，无幂等键 |
| POST `/join-applications` | 登录 | `{token?: string, code?: string}` 二选一 → Application |
| GET `/me/join-applications` | 登录 | 本人的 Application 分页列表 |
| POST `/join-applications/{a}/withdraw` | 申请人 | 无 → Application |
| GET `/groups/{g}/join-applications` | 管理者 | `status?, cursor?, limit?` → Application 分页列表 |
| POST `/groups/{g}/join-applications/{a}/decision` | 管理者 | `{decision: APPROVE|REJECT, reason?: string}` → Application |
| GET `/groups/{g}/audit-logs` | 管理者 | `action?, cursor?, limit?` → AuditEntry 分页列表 |

Invitation token 至少 128 位随机值，用于小程序分享参数；手工邀请码用 12 位不易混淆字符。两者只保存哈希；邀请码查询和申请按用户/IP 限流。token 不放进业务日志。`uses` 指成功提交的新申请数，撤回/拒绝不归还；重复待审批申请不计数。再次审批同一终态决定返回现有结果，反向决定返回状态冲突。role 接口用 member 的独立版本，Group 版本仅用于群资料及所有权。

### 多群协议补充

一个用户可反复调用 POST /groups 创建不同群，每次新建意图使用不同幂等键，相同键重试仍只创建一次。创建群自动建立本人群主成员关系，不需要再申请加入。

切群不需要重新登录、刷新令牌或调用“设置当前群”接口。客户端选择 groupId 后调用 GET /groups/{g} 获取最新 GroupContext；所有群内操作显式携带路径 groupId。服务端不得从最近访问群或会话全局状态推断业务归属，必须按该群成员关系重新检查权限。群列表的统计通过聚合查询取得，避免逐群额外查询。

## 5. 积分

| 方法与路径 | 权限 | 请求 / 返回 |
|---|---|---|
| GET `/groups/{g}/me/account` | 成员 | Account |
| GET `/groups/{g}/me/ledger` | 成员 | `type?, cursor?, limit?` → LedgerEntry 分页列表 |
| GET `/groups/{g}/members/{m}/ledger` | 管理者或本人 | 同上 |
| POST `/groups/{g}/point-entries` | 管理者 | `{memberId, type: GRANT|ADJUSTMENT, delta, reason}` → `{entry: LedgerEntry, account: Account}` |
| POST `/groups/{g}/point-entries/{e}/reversal` | 管理者 | `{reason}` → `{entry: LedgerEntry, account: Account}` |

GRANT 的 delta 必须 >0；ADJUSTMENT 必须非零；reason 去除首尾空白后 1–200 字。禁止目标为操作者自身。REVERSAL 由服务端计算相反 delta，只接受本群 GRANT/ADJUSTMENT 且没有被冲正的记录；不接受客户端传入反向数额。余额上限检查与余额不足检查均在锁定账户后执行。

## 6. 奖励与图片

| 方法与路径 | 权限 | 请求 / 返回 |
|---|---|---|
| GET `/groups/{g}/rewards` | 成员 | `type?, cursor?, limit?` → ACTIVE Reward 分页列表 |
| GET `/groups/{g}/rewards/{r}` | 成员 | ACTIVE Reward；管理者可查看其他状态 |
| GET `/groups/{g}/managed-rewards` | 管理者 | `status?, cursor?, limit?` → 全状态 Reward 分页列表 |
| POST `/groups/{g}/rewards` | 管理者 | `{name, description?, imageAssetId?, type, costPoints, initialStock, fulfillmentInstructions}` → DRAFT Reward |
| PATCH `/groups/{g}/rewards/{r}` | 管理者 | `{name?, description?, imageAssetId?, costPoints?, fulfillmentInstructions?, expectedVersion}` → Reward |
| POST `/groups/{g}/rewards/{r}/status` | 管理者 | `{status: ACTIVE|INACTIVE, expectedVersion}` → Reward |
| POST `/groups/{g}/rewards/{r}/stock-adjustments` | 管理者 | `{delta: nonzero int, reason, expectedStockVersion}` → `{reward: Reward, adjustmentId}` |
| POST `/assets/upload-intents` | 登录 | `{purpose: AVATAR|GROUP_AVATAR|REWARD_IMAGE, groupId?, contentType, sizeBytes}` → `{assetId, uploadUrl, requiredHeaders, expiresAt}` |
| POST `/assets/{a}/complete` | 上传者 | 无 → `{assetId, status: READY, url}` |

图片上传意图先检查用途权限，群图片要求 groupId 和管理权限；仅接受 JPEG/PNG/WebP，最大 5 MiB。上传地址有效 10 分钟，限制对象路径和写入权限。complete 在服务端核验对象大小、实际文件类型及图片有效性，不能只信客户端 MIME。业务引用仅允许 READY 且用途/群一致的 assetId；返回 URL 由服务端生成。首版头像及奖励展示图为可公开读取的非敏感素材，不支持上传证件或私密附件。

reward.version 只在文案/价格/上下架时递增；stockVersion 在库存变动时递增。普通兑换竞争只影响 stockVersion，不让另一个有效兑换因为无关库存版本变化而失败。

## 7. 兑换订单与核销

| 方法与路径 | 权限 | 请求 / 返回 |
|---|---|---|
| POST `/groups/{g}/redemptions` | 成员 | `{rewardId, expectedRewardVersion, expectedCostPoints}` → `{order: Redemption, account: Account}` |
| GET `/groups/{g}/me/redemptions` | 成员 | `status?, cursor?, limit?` → 本人 Redemption 分页列表 |
| GET `/groups/{g}/redemptions` | 管理者 | `status?, memberId?, cursor?, limit?` → 全群 Redemption 分页列表 |
| GET `/groups/{g}/redemptions/{o}` | 本人或管理者 | Redemption |
| POST `/groups/{g}/redemptions/{o}/cancel` | 本人或管理者 | `{reason}` → `{order: Redemption, account: Account}` |
| POST `/groups/{g}/redemptions/{o}/claim-token` | 订单本人 | 无 → `{token, manualCode, expiresAt}` |
| POST `/groups/{g}/redemption-claims/preview` | 管理者 | `{token?: string, manualCode?: string}` 二选一 → `{order: Redemption, claimant: {memberId, displayName}}`；只读，无幂等键 |
| POST `/groups/{g}/redemptions/{o}/fulfill` | 管理者且非本人 | `{method: TOKEN|MANUAL, token?: string, manualCode?: string, note?: string}` → Redemption |

TOKEN 核销要求 token/manualCode 二选一且匹配订单和群；MANUAL 不接收 token，note 必填 1–200 字。核销前二次确认实物/权益已交付。

核销 token 至少 128 位随机值，手工码为 10 位随机数字，有效期 5 分钟。按订单保存 generation，刷新码使旧代失效，完成/取消使所有码失效。数据库保存哈希及加密后的响应材料以支持相同幂等键安全重放；前端码过期后用新幂等键获取。按群+管理员/IP 限制猜码。扫码内容不得包含用户身份数据。

兑换的 memberId 和 costPoints 均由服务端确定；expectedCostPoints 仅用于确认一致性，不是计费依据。第一版数量固定 1。

## 8. 错误码与前端动作

| HTTP | code | 前端行为 |
|---|---|---|
| 400 | VALIDATION_ERROR | 定位字段，保留输入 |
| 401 | UNAUTHENTICATED | 刷新会话或重新登录 |
| 403 | FORBIDDEN / SELF_OPERATION_FORBIDDEN | 提示权限/不能操作本人，刷新能力 |
| 404 | RESOURCE_NOT_FOUND | 返回列表，不泄露跨群资源存在性 |
| 409 | VERSION_CONFLICT / REWARD_CHANGED | 获取最新数据并重新确认 |
| 409 | INSUFFICIENT_POINTS / OUT_OF_STOCK | 刷新余额/库存 |
| 409 | BALANCE_LIMIT_EXCEEDED / STOCK_LIMIT_EXCEEDED | 提示超出允许范围 |
| 409 | INVALID_STATE / ALREADY_REVERSED | 刷新流水/订单状态 |
| 409 | IDEMPOTENCY_KEY_REUSED | 同键不同请求，禁止自动生成新键重试 |
| 409 | OPERATION_IN_PROGRESS | 短暂退避后用原键重试 |
| 410 | INVITATION_EXPIRED / INVITATION_REVOKED / CLAIM_EXPIRED | 重新获取邀请/核销码 |
| 409 | INVITATION_EXHAUSTED | 请求新邀请 |
| 404 | INVITATION_NOT_FOUND / CLAIM_NOT_FOUND | 提示无效，不提供猜测线索 |
| 429 | RATE_LIMITED | 根据 Retry-After 等待 |
| 503 | TEMPORARILY_UNAVAILABLE | 退避，写操作保留原键重试 |

数据库死锁/序列化失败由服务端最多重试 3 次，每次重新开启完整事务，保持原幂等键；仍失败返回 503。客户端超时不能推断事务失败。

## 9. 幂等与版本契约

幂等唯一范围为 `(userId, operationScope, key)`；operationScope 包含 HTTP 方法及具体路径（含资源 ID），requestHash 为归一化请求体的哈希。服务端先认证、确认当前资源访问权，再查询/抢占幂等记录；同键不同内容返回冲突。

幂等记录与业务写入同事务提交，冲突请求等待前一个事务，超出等待阈值返回 OPERATION_IN_PROGRESS；原事务回滚时记录一并回滚。只缓存已提交成功结果，确定性业务失败不占键；用户改变表单内容代表新意图，必须生成新键。

成功记录第一版不定期删除，不能 TTL 到期后重新执行历史积分请求。含邀请/上传/核销秘密的响应加密保存，禁止日志输出。过期临时链接按原响应返回，前端明确发起新请求重新生成。返回的余额为原操作完成时余额，重放后需 GET 刷新当前账户。

版本控制解决多人编辑覆盖；幂等键解决同一次请求重复提交；数据库事务和约束解决并发账目一致性，三者不能互相替代。
