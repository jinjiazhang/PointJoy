# 代码规范

## 日常命令

在仓库根目录运行：

```sh
npm run format       # 自动统一源码、测试和配置的格式
npm run lint         # ESLint、Prettier 检查和两个工作区的类型检查
npm run check        # 规范检查、全部测试及 API / H5 / 微信小程序构建
```

数据库测试使用 README 中列出的五个专用测试库。运行前核对连接参数；不要使用业务数据库。

## 排版与命名

- 使用 2 空格缩进、单引号、分号和尾逗号，建议每行不超过 100 列。以 `.prettierrc.json` 和 `.editorconfig` 为准，不手工压缩源码。
- 每条变量声明只声明一个变量；不重新赋值时使用 `const`。条件和循环的语句体使用大括号。
- 函数和变量使用 `camelCase`，类型及 Vue 组件使用 `PascalCase`。命名说明业务含义，避免无必要的缩写。
- 删除未使用的导入和变量；必须保留的回调占位参数使用 `_` 前缀。忽略返回值时，仍需保留权限校验、数据库查询和写入等调用。
- 对外输入使用现有 Zod schema 校验。已有动态数据库结果逐步补充类型，不用批量类型断言掩盖错误。
- 注释解释约束、原因和边界；复杂映射和判断放在脚本中，模板侧保留展示逻辑。

## 模块职责

后端 `apps/api/src/common` 按职责组织：

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 数据库连接、操作者、服务配置与共享接口 |
| `errors.ts` | 业务错误 |
| `database.ts` | PostgreSQL 类型转换、查询与事务 |
| `responses.ts` | 响应包体、状态标记与列表结果 |
| `mutations.ts` | 权限复核、行锁、幂等记录与事务重试 |
| `audit.ts` | 审计记录、Outbox 与安全保护事件 |
| `utilities.ts` | 规范化序列化、作用域签名、日期与版本校验 |
| `index.ts` | 对外导出入口 |

模块内部直接引用所需文件，避免通过自己的 `index.ts` 形成循环依赖。领域规则继续放在 `domain` 中；数据库生效窗口使用数据库时间判断，与发布时的时间来源保持一致。

前端 `apps/mini/src/services/api.ts` 保留统一调用入口，具体实现分为 `transport.ts`（请求、登录刷新和分页）、`operations.ts`（幂等写入与未确认操作恢复）、`paths.ts`（家庭和孩子路径）以及 `query.ts`（查询参数编码）。导航也复用相同的查询参数编码。

`pages` 下的页面只指定 feature screen 和页面名称，通过 `useScreenPage` 读取页面参数并转发显示及下拉刷新事件。feature screen 使用 `usePage` 处理数据加载、权限守卫和操作反馈。

## 变更边界与验证

- 保留 API 字段、持久化存储键、事务边界、锁顺序、幂等键及权限约束；拆分文件后保留对外导出，减少调用方迁移。
- 新增或修复业务行为时补充覆盖该行为的测试。纯排版和文件拆分复用已有回归测试。
- SQL 迁移有内容校验，已执行的迁移不参与格式化；数据库变更通过新迁移完成。
- `dist`、生成的 OpenAPI 契约、依赖锁文件、运行数据和密钥不参与格式化。生成产物应通过对应工具更新。
- `npm run check` 是 CI 模板和本地交付的统一入口。
