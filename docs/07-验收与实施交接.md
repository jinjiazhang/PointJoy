# 积乐圈家庭版：验收与实施交接

更新：2026-09-20 · 状态：当前验收标准；各项执行结果以测试及发布记录为准。

本文将当前设计转成可执行验收条件。验收结果应提供对应测试与发布证据。业务规则以 [00-规则基线](./00-规则基线.md) 为统一契约；需求、页面、接口与本清单必须在同一个发布版本内保持一致。

## 1. 交接范围与完成定义

P0 的完成标准是：所有使用者经微信登录和强制上传头像、填写昵称后，单家长可独立代办全流程；孩子也可绑定自己的微信账号直接使用。同一个孩子档案共享一套计划、历史和账本，可附照片完成活动，并能安全处理错误、断网、多孩子切换和数据退出。所有 P0 入口必须可用，不以按钮、原型或仅有接口代替闭环。

下表每个验收编号均为 P0 必过项。实施团队可拆成多个自动化用例，但不得删去业务断言。头像上传、孩子微信账号绑定、可选完成照片均为 P0。P1 的能力不应出现在 P0 的可点击操作中：奖励自定义封面、持续计时、部分权益消费、每周累计目标、批量审批、微信订阅消息、归档档案恢复。

测试结果至少记录：版本/提交号、环境、设备和微信版本、用例编号、输入与时间、请求关联 ID、页面结果、业务状态与账务断言、证据位置、执行人、执行日期。账务正确性必须核对持久化记录，不能只截取成功弹窗。

## 2. 家庭、身份与模式验收

| 编号 | Given：前置条件 | When：操作 | Then：必须成立 |
| --- | --- | --- | --- |
| F01 | 新微信账号（分别以家长和孩子测试） | 登录、接受隐私说明、上传有效头像、填写昵称并成功保存资料 | 仅在服务端原子设置 profileCompletedAt 后放行业务；不要求实名或真人脸部照片；拒绝隐私说明时不创建业务家庭 |
| F02 | F-A 仅有妈妈一个成人 | 创建两个孩子，为小星代录、申请奖励、批准、兑现 | 全部可由同一成人完成；受益者为小星，操作者为妈妈；成人没有积分账户 |
| F03 | 家长已微信登录且资料完整，孩子尚未绑定自己的微信 | 家长上传孩子档案头像、填写昵称并安排计划 | 家长可代办或进入 DELEGATED 受限模式；不强制先绑定孩子微信；不要求手机号、学校、精确生日、住址或定位 |
| F04 | 妈妈已加入 F-A、F-B | 切换家庭，同时让 F-A 的慢请求晚于 F-B 返回 | 只显示 F-B 数据与权限；余额、孩子、表单、待办不串家庭；不可把 F-A 草稿提交给 F-B |
| F05 | 家长已选小星，存在尚未提交草稿 | 切换到小月 | 页面明确变为小月；草稿仍绑定原孩子；不会静默迁移或提交；小月不能看见小星私有记录 |
| F06 | 妈妈处于家长模式 | 进入小星 DELEGATED 孩子模式，随后重放原家长 token | 小星会话只允许其本人范围；原家长 token 服务端失效或降权；不得继续执行管理请求 |
| F07 | 当前处于小星 DELEGATED 孩子模式 | 返回、重启小程序、打开管理深链、改请求 childId、尝试切换小月 | 均不能获得家长或小月权限；退出/切换须完成源家长 PIN 验证并换取适当权限 |
| F08 | 孩子模式下有提交结果未确认 | 退出或切换孩子/家庭 | 原操作仍由原身份安全确认；新页面不接受旧响应覆盖；未知结果未被当成失败重新下单 |
| F09 | 已设置成人账户的 6 位 PIN 与一次性恢复码 | 连续输错、达到限流、尝试恢复 PIN、从孩子会话直接请求重置 | 错误不泄露 PIN；服务端限流；恢复需有效的一次性恢复码，不能凭孩子会话或微信静默登录重置；成功恢复后撤销全部会话、旧恢复码失效 |
| F10 | OWNER 生成成人邀请 | 同一受邀账号重复申请、负责人重复批准 | 只建立一份有效成员关系；不建立成人积分账户；邀请成功消耗一次；无重复成人 |
| F11 | 邀请无效、已撤销、满 24 小时、已成功使用，或两人同时请求批准 | 分别尝试加入/批准，包括到期前申请而到期后批准 | 批准时必须仍有效且未撤销/使用；最多首个批准成功加入；其余批准失败；失败不泄露家庭成员或孩子资料 |
| F12 | 外婆为共同家长 | 日常审核、管理奖励、尝试邀请/移除成人/转让负责人 | 日常业务可用；负责人专有操作后端拒绝；角色不能通过客户端字段伪造 |
| F13 | 外婆及其派生孩子会话已登录 | OWNER 移除外婆，再用旧页面与 token 读写 | 家庭访问即时失效，派生孩子会话失效；历史操作者仍可追溯 |
| F14 | 妈妈为负责人 | 转让给有效共同家长；原负责人退出；最后成人尝试退出 | 同一事务后恰有一名负责人；新负责人权立即生效；负责人未转让不能退出；最后成人走归档流程 |
| F15 | 任一未授权成人或孩子会话 | 枚举/替换其他家庭、孩子、计划、订单、流水、导出请求 ID | 所有读写接口都拒绝越权；错误不返回越权资源内容；猜不到 ID 不能替代授权校验 |
| F16 | 微信账号已经设置过 PIN | 孩子清除本地数据、注销后重新微信登录或换一部设备登录 | 服务端返回 LOCKED 受限会话；PIN 验证前不可管理、不能重新设置免验证 PIN；换设备不绕过家长模式锁 |
| F17 | 无会话、伪造微信身份、失效/被重放的 code | 调用登录/家庭接口、前端选择“我是家长” | 服务端验证微信身份；拒绝假身份和无效凭据；真实微信身份只证明账号，不自动建立监护关系或升级既有家庭权限 |
| F18 | 仅填昵称、头像仍是占位、上传失败、头像上传成功但资料保存失败 | 重启、返回、直达分享页、手工请求家庭/提交/兑换接口 | 保持 PROFILE_ONLY 或必要的 LOCKED；只允许最少资料/公开说明白名单；家庭与孩子内容不泄露；不能凭本地完成标记放行 |
| F19 | 账号/新孩子档案尚无有效上传头像 | 提交空头像、内置占位 key、外站 URL、其他用途或他人的媒体 ID | 全部拒绝；用户上传自选插画或照片验证成功后可用；头像无需为真人照片 |
| F20 | U-C 为 DIRECT，妈妈设备处于 DELEGATED | 分别进入账号资料/隐私子页或直接请求对应接口 | DIRECT 只能改自己的头像昵称/申请自己的数据；DELEGATED 不可访问或修改源家长资料/发起源家长个人导出；双方均不能改其他孩子账号 |
| F21 | 资料页已填昵称并选择头像 | 上传失败、处理失败、保存超时、取消相册选择后重试 | 保留昵称和明确图片状态；处理 READY 才可完成资料；原 key 确认保存结果；下次登录资料完整不重复强制换头像 |
| F22 | OWNER 对未绑定的小星生成 CHILD_BIND 邀请，U-C 已完整资料 | U-C 申请，负责人核对头像昵称和目标后批准，分别测试同步/不同步资料 | 申请明确向负责人展示资料；头像读取仅限该申请；同步走受控 CHILD_AVATAR 派生引用，不放宽通用媒体权限；绑定唯一 User，DIRECT 与家长代办共用原档案/账本；申请和批准幂等 |
| F23 | 孩子已绑定、账号已绑定本家庭其他孩子、账号已为本家庭家长，或两人并发争同绑定 | 申请/批准绑定 | 拒绝冲突且不覆盖原绑定；最多一笔成功；同一家庭不能身兼家长与孩子；失败不创建第二账户 |
| F24 | CHILD_BIND 已撤销/到期/已用；或尝试替换 childId、用成人邀请当孩子邀请 | 申请或批准，包括期限前申请期限后批准 | 目标只从有效邀请读取；用途不可互换；批准时重新核对有效性；错误申请可撤回/拒绝 |
| F25 | U-C 已 DIRECT 登录并读取过自己的活动照片 | OWNER 解绑，再用旧 token/媒体请求访问或提交 | 旧 DIRECT 服务端授权立即失效；清理应用作用域缓存；原孩子账本/历史和家长代办保留；已下载到设备的文件不承诺远程收回 |
| F26 | U-C 通过 DIRECT 登录 | 打开 PIN 页、提交源家长 PIN、修改 mode、打开家长路由 | 不能用 PIN 升级为家长；可退出自己的登录；服务端绑定权限不受客户端角色字段影响 |
| F27 | 一个 User 在不同家庭合法具有不同关系 | 切换家庭并重放旧范围请求，或修改自己的账号昵称 | 每个家庭独立鉴权，不凭其他家庭的家长身份越权；账号资料更新不改写孩子已发生账务/操作快照 |
| F28 | 成人加入申请或孩子绑定申请仍为待处理 | 申请人撤回，同时负责人尝试批准 | 最多一个有效转移；撤回先成功则不可再批准；不消费成功邀请次数/绑定；若批准已先成功则显示真实结果，不把撤回当退出/解绑 |

## 5. 精确账务验收夹具

### 5.1 连续完整脚本：预留、批准、返还、兑现

独立初始化小星账户 `available=0, held=0, version=0`；R-F 价格 30，有限可用库存 2，每周限 2。所有步骤发生在同一自然周。每行是一次成功的业务动作；无账户变化的动作不得伪造积分流水。

| 步骤 | 动作/订单结果 | 本次 available 变化 | 本次 held 变化 | 结果 available / held | 可用库存 | 本周占额 | 累计赚取 / 兑换支出 / 退款 |
| --- | --- | ---: | ---: | --- | ---: | ---: | --- |
| L01 | 手动表扬 +100 | +100 | 0 | 100 / 0 | 2 | 0 | 100 / 0 / 0 |
| L02 | 申请 O1 → PENDING_APPROVAL | -30 | +30 | 70 / 30 | 1 | 1 | 100 / 0 / 0 |
| L03 | 申请 O2 → PENDING_APPROVAL | -30 | +30 | 40 / 60 | 0 | 2 | 100 / 0 / 0 |
| L04 | 批准 O1 → READY | 0 | -30 | 40 / 30 | 0 | 2 | 100 / 30 / 0 |
| L05 | 拒绝 O2 → REJECTED | +30 | -30 | 70 / 0 | 1 | 1 | 100 / 30 / 0 |
| L06 | 取消 O1 → CANCELED | +30 | 0 | 100 / 0 | 2 | 0 | 100 / 30 / 30 |
| L07 | 申请 O3 → PENDING_APPROVAL | -30 | +30 | 70 / 30 | 1 | 1 | 100 / 30 / 30 |
| L08 | 批准 O3 → READY | 0 | -30 | 70 / 0 | 1 | 1 | 100 / 60 / 30 |
| L09 | 实际交付并确认 O3 → FULFILLED | 0 | 0 | 70 / 0 | 1 | 1 | 100 / 60 / 30 |
| L10 | 申请 O4 → PENDING_APPROVAL | -30 | +30 | 40 / 30 | 0 | 2 | 100 / 60 / 30 |
| L11 | O4 满 72 小时 → EXPIRED | +30 | -30 | 70 / 0 | 1 | 1 | 100 / 60 / 30 |

应核对以下结果：账户变动流水 10 条，账户版本从 0 连续递增到 10；L09 有业务审计、没有积分/库存变动流水；本脚本新增有限库存流水 7 条，累计 `-4+3=-1`，加上夹具初始化 `INITIAL +2` 一条共 8 条库存流水，结果库存 1；实际总持有为 70，净兑换支出为 `60-30=30`。预留/释放不能记为新的赚取或兑换支出。L05 不是退款，因为该订单从未正式扣款；L06 是退款，累计兑换支出与退款分列保留原事实。

任一步骤用同 key 重放 3 次，返回同一操作结果且上述行数、版本和数值不变。幂等返回应与操作查询可关联；不能为每次重放创建新订单、流水或库存流水。

### 5.4 新发分上限与全额返还

1,000,000 是新发分的准入上限，不是禁止退款的硬上限。退款可使余额暂时超出；此时暂停新发分。数据库使用非负 64 位整数，API 校验安全整数；不能用数据库 `CHECK(total <= 1000000)` 阻断合法退款。

下列步骤使用独立账户和无限库存、无每周限额的测试奖励，初值 available 999,980、held 0；初值必须由可对账夹具建立。

| 编号 | 动作 | 必须得到的数值与结果 |

## 10. 外部数据导入边界

外部系统数据导入使用独立开发/测试环境演练，并制定迁移映射与对账方案。导入流程不允许删除、重置或自动改写来源不明的现有数据。

| 旧数据 | 迁移处理边界 |
| --- | --- |
| User 微信身份 | 可在取得授权并确认同主体后复用登录标识；不得导出 token、原 PIN 或平台密钥；积乐圈重新签发会话 |
| Group 与 Member | 不自动把群认定为家庭，不把普通成员/管理员直接推断为孩子/家长；由负责人逐一确认家庭和成人关系 |
| 成人 Member 的余额 | 不自动分配到同名孩子；明确归属与账本起点后才导入；不能凭昵称匹配或静默清零 |
| 旧积分流水 | 保留只读历史与原来源 ID；导入账务需有单独可识别的期初类型和对账报告，不伪装成孩子完成新活动 |
| DailyRoutine/Event 与参与记录 | 不以当前规则回算旧达标；存历史快照与旧状态语义；迁入新计划需人工确认适用孩子、生效日和新目标 |
| 旧 PENDING 兑换 | 旧系统已扣款且待领取，不能直接当新 PENDING_APPROVAL 再预留/扣款；优先旧系统结清，否则经核对映射 READY 并标记历史已支付 |
| 旧 FULFILLED/CANCELED | 保留终态事实与快照；不触发新发分/退款/回库；不重复占用积乐圈周额度 |
| 库存 | 以切换时账面数量与实物约定共同确认；待履约订单对应占用不得二次扣减；发布后模式选择须明确 |
| 邀请、会话与缓存 | 不继承旧邀请/会话；生成新权限关系；清理失效缓存；不能保留旧成人 token 绕过孩子模式 |

迁移必须经过：脱敏抽样演练 → 映射确认 → 全量备份 → 明确切换窗口及写入归属 → 试迁移 → 逐家庭/孩子余额、待兑现权益与库存对账 → 负责人确认 → 正式迁移 → 观察与回滚验证。新旧系统同时可写期间必须有唯一写入归属，不允许两边独立增减同一笔积分。

没有逐条映射的记录进入人工待确认清单，不被悄悄丢弃。迁移后先核对“孩子还有多少可用积分、多少在申请、家长还欠哪些奖励”，再核对汇总报表；任一无法解释的差额均阻止切换。
