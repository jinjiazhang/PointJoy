# 积乐圈家庭版 · 交互文档

版本：1.0 · 2026-09-19 · 交付对象：产品、交互、前端、测试。

本文定义完整 P0 的页面、路由、操作与异常恢复；[00-规则基线.md](./00-规则基线.md) 是业务契约。已纳入用户最新确认：全部使用者微信登录，首次真实上传头像并填写昵称，孩子可独立微信登录或由家长代办，完成照片为 P0 可选项。页面编号用于需求、设计稿与测试引用，不强制等于源码目录。与本文同目录的 [设计预览.html](./设计预览.html) 仅演示核心链路，页面未出现在预览中不等于从 P0 删除。

## 1. 体验目标与角色

家长的主要任务是建立可执行的家庭约定、判断完成情况、及时兑现承诺。孩子的主要任务是看懂今天要做什么、表达自己完成了什么、选择想要的奖励。积分表达一项约定的完成结果，不展示家庭成员排名、不设置连续打卡惩罚、不用倒计时或稀缺话术催促兑换。

| 模式 | 可用操作 | 身份信息位置 |
| --- | --- | --- |
| 家长模式 · OWNER | 所有日常管理，以及邀请/移除成人、转让负责人、家庭归档、导出/删除申请 | 每个主页面顶部显示家庭；操作确认显示孩子昵称 |
| 家长模式 · GUARDIAN | 计划、孩子日常管理、积分表扬/纠错、活动审核、奖励与订单；可退出当前家庭 | 同上；负责人专属入口隐藏，直达仍由服务端拒绝 |
| 孩子视角 · DIRECT | 自己的微信登录并绑定档案；本人任务、照片、心愿、兑换、成长及本人账号设置 | 顶部常显本人昵称和“自己的微信”；仅可切自己已有合法关系的最小上下文，无其他孩子列表 |
| 孩子视角 · DELEGATED | 已登录家长共用设备中的受限会话；仅本人任务、照片、心愿、兑换与成长 | 顶部常显本人昵称、“共用家长设备”及 PIN 家长入口；无家庭切换和其他孩子列表 |

家长没有积分余额。家长代孩子提交、审核自己的代录、申请兑换、批准及兑现均合法；不得出现“不能审核自己”之类沿用旧系统的拦截。

## 3. 全局交互契约

### 3.1 统一加载、错误与返回

下表适用于全部页面，每页下面仅补充其特有状态，设计交付必须包含这些公共组件。

| 情况 | 显示及可用动作 | 不允许的行为 |
| --- | --- | --- |
| 首次读取中 | 页面骨架、标题和返回可用；按钮不出现可操作假数据 | 把余额初值 0 显示成真实账户 |
| 下拉刷新 | 保留已有数据并标示刷新；返回服务端状态后一次更新关联摘要 | 先把余额改为估计值 |
| 首次读取失败 | 「暂时没能加载」+ 重试；保留上下文与筛选 | 一律显示“没有内容” |
| 已有缓存且离线 | 「网络未连接，显示上次内容」+ 最近同步时间；仅浏览 | 离线发送会改积分/库存/权限的操作 |
| 列表为空 | 解释当前筛选或初始化情况；提供清除筛选或本角色合法的建立入口 | 孩子空态出现管理入口 |
| 字段不合法 | 字段下方短句 + 聚焦首个错误；保留所有输入 | 仅用 toast 或在发送后清空表单 |
| 写入进行中 | 按钮「提交中…」、防重复；保留取消导航的安全提示 | 同时允许第二个相同写请求 |
| 写入结果未明 | S04 内嵌状态区「结果尚未确认」+「查询结果」；保存原操作标识 | 显示“操作失败”并用新 key 重做 |
| 状态/版本冲突 | 「已由另一位家长处理」或「内容已更新」；展示最新状态，再决定新操作 | 自动覆盖别人的修改 |
| 权限失效/孩子已归档 | 清除敏感缓存，返回当前可访问入口；中止写操作 | 仍可查看先前的其他孩子数据 |
| 返回未保存表单 | 「继续填写 / 放弃修改」；仅纯表单草稿可以丢弃 | 用“放弃修改”取消已被服务端接受的业务 |
| 返回列表 | 更新被改变的行与聚合数，保留滚动；必要时重拉当前筛选 | 只改详情、不改余额和待办数 |

分页列表都提供加载更多、失败重试、已到底；历史总数和摘要来自完整统计接口，不能通过已加载的行数推算。顶部家庭选择和孩子筛选始终显示当前值；“全部孩子”只提供给家长，不把任何孩子余额相加显示为“家庭余额”。

### 3.2 确认层级与请求恢复

普通创建编辑使用页面末尾一次明确提交；审批、发分、申请兑换等在原页面显示关键后果后可直接确认，不再重复弹相同文案。撤销积分、取消已批准订单、停止挑战、归档、移除成人、转让负责人使用独立确认面板，按钮直接写后果，例如「确认撤销 10 积分」。

网络超时后：客户端保存不可变的原请求内容、操作 ID 和幂等 key → 显示未确认 → 按原操作查询 → 查到成功则显示原结果；查到明确失败则允许修正后发起新操作；查询仍不明则保持等待。必须重新发送时沿用同一 key 和原内容。重启后先恢复未确认操作；重新登录后仅在同一授权主体/作用域下恢复，不替换成另一位成人或另一名孩子。

未确认操作影响的孩子/订单暂时禁止冲突写入，其他只读页面可浏览。进入孩子模式、换家庭、退出登录前优先确认待定写入；离线时可取消切换返回原页，不得丢掉待定操作或宣称已取消。重新取得当前身份后仍无法确认则显示服务支持所需的请求号，不要求用户重复下单。

## 4. 共享页面详细规格

### S01 微信登录与独立强制资料页

S01a 首次画面依次是「给努力一点回应」、用途一句话、隐私说明链接、未默认勾选的同意项和「微信登录」。用户同意后才执行登录相关请求；不同意可退出。所有使用者都须微信登录，没有匿名孩子入口；角色从已有关系和合法邀请确定，不能靠选择“我是家长”升级某家庭权限。

S01b 在账号资料未完整时独立显示：头像上传（必填）、昵称（去首尾空白后 1—24 字，必填）和「保存并继续」。成人可以填写“爸爸”“姥姥”，孩子可以填昵称，不要求实名。头像必须是用户选择并被服务端成功处理的上传文件，可用自选插画、不强制真人脸；占位图、默认内置图、失效临时地址、只有昵称都不算完成。选择文件后提供方形裁剪预览，成功处理后显示“头像已上传”，保存头像媒体 ID 和昵称成功且服务端确认 `profileCompletedAt` 后才允许进入业务。

头像支持 JPEG/PNG/WebP，原文件 ≤10 MiB、≤4,000 万像素，服务端真实格式检查、去 EXIF/GPS、裁为 512×512 JPEG。上传中/处理中禁用继续；单张失败保留昵称和先前有效头像，提供重新选择/重试。拒绝相册权限、取消选图仍留在资料页，不能跳过必填头像；说明可从相册选择喜欢的图，无须拍摄真人。保存请求失败保留输入，结果未明转 S04 查询原操作。返回、重启、深链、分享目标不能绕过资料页，PROFILE_ONLY 下不请求家庭业务数据。

已有完整资料再次登录不需重复上传，但仍检查头像有效性和资料完成标记。成人账户一旦设置 PIN，此后微信重新登录先 LOCKED，经 S03 验证后仍要检查资料完整性；未设 PIN 的新账号可以先完成资料和家庭建立。S01b 成功后恢复 S02/邀请流程/原合法目标，失效目标回到可访问上下文。孩子本人账号失效只能重新登录本人微信；共用家长设备失效不能自行变为完整成人权限。

### S02 家庭选择与加入

服务端仅返回本 User 已授权的最小上下文（家庭名、本人角色、本人绑定的孩子标识），点击一行后再加载该作用域业务。DIRECT 可选择自己已绑定的上下文，不可列出兄弟姐妹；进入另一个已有家长关系的上下文时，已启用 PIN 的 User 仍须验证，不能绕过 LOCKED；尚未启用 PIN 的合法家长可先完成家庭配置。没有关系时提供「创建家庭」「我收到成人邀请」「我收到孩子绑定邀请」，均不产生既有家庭权限。创建字段为家庭名 2—30 字，合法创建者成为新家庭负责人并引导 P12 新增孩子，可暂不建孩子返回空首页。

成人邀请链接打开后，未登录走 S01，资料不完整先完成 S01b，再展示最少必要信息（家庭名、邀请人称呼、24 小时有效期）和「申请成为共同家长」。不得在批准前泄露孩子昵称、余额、照片或记录。申请后页面显示「等待负责人同意」，可主动刷新或撤回申请。批准后进入 P01；拒绝、撤销、过期、已用完分别说明，可返回家庭列表。相同申请重复发送显示原待处理申请；一次成功入会后令牌不可再用。

CHILD_BIND 邀请使用独立标题「绑定我的孩子账号」，不复用成人加入按钮。本人完成 S01b 后申请，目标 childId 由邀请确定，客户端不可修改；等待负责人核对账号上传头像和昵称。批准成功进入对应 C01 DIRECT；拒绝/撤回/失效保留明确结果；未通过前不读取孩子历史和照片。同一家庭已有家长身份、已绑定另一孩子或目标已有账号时，显示冲突说明并要求负责人处理，不能自动解绑/覆盖/新建第二本积分账。

多家庭切换先完成或保留原未确认操作，清空旧家庭上下文，慢响应按家庭标识丢弃。用户被移除后返回仍能访问的家庭列表，不能静默创建一个新家庭。

### S03 PIN 与模式切换

首次进入 DELEGATED 孩子模式，家长先设置账户级 6 位数字 PIN，重复输入一致后保存；界面说明「这个密码只给家长使用」。随后显示一次性的 128 位高熵恢复码，提供复制/安全保存动作，并要求明确确认已妥善保存，才允许完成开启流程；恢复码不是六位 PIN，不能自动保存在孩子可访问的页面。数字框支持键盘粘贴和删除，按密码字段处理，禁止明文回显。选择孩子后显示「接下来只显示朵朵的内容」及「进入孩子模式」，服务端成功降权/撤销成人会话并发放绑定该家庭与孩子的受限会话后，才进入 C01。

DELEGATED 顶部入口为小型但可辨识的「家长入口」，点开后需源家长 PIN 验证。验证正确并换得家长权限才返回 P01 或此前请求的家长页；验证前不能显示其他孩子昵称、管理列表或预载其数据。切换孩子同样须先通过 PIN，回到家长的孩子选择页，再进入新会话。点击取消回到原孩子页面，返回键和重新启动不能绕过。DIRECT 顶部提供「账号设置」，无家长 PIN 入口，只能退出本人的登录或选择本人另有授权的上下文；退出不会自动借用设备上的另一个成人账号。

输入错误提示「密码不正确，请再试一次」，不告诉哪一位错；达到服务端限流条件显示等待时间。忘记 PIN 必须先微信验证账号，再验证预先保存的恢复码，重置后吊销全部会话和旧恢复码，产生新恢复码并再次确认保存；微信登录本身不能重置或绕过 PIN。已解锁成人会话可按技术规范修改 PIN。恢复码也遗失时提供支持渠道及无法自动解锁的说明，不用孩子生日、问答题或静默登录兜底；其他负责人可按既有治理流程移除旧成员并邀请另一成人账号，但不解除原账号的锁定。进入/退出模式网络结果未明先查询会话状态，不能同时保留两套可写 token。HTML 预览中的公开 PIN 仅用于解释这一流程，生产不得写死 PIN。

### S04 操作恢复与失效

显示动作名、目标昵称、发起时间、「正在确认服务器结果」以及请求号。查询成功显示原业务结果并提供「查看记录」；明确失败回原表单且保留输入；授权失效先恢复相同身份。恢复区不能带“重新兑换”按钮，查询失败不等于原操作失败。权限不足文案统一为「当前身份无法访问此内容」，不暴露其他家庭资源是否存在。

## 5. 家长页面详细规格

### P01 首页

首屏依次为家庭切换与问候、日期、三项待办（待审核完成/待批准兑换/待兑现奖励）、孩子卡片与「记录完成」。孩子卡展示今天已通过/应完成、待审核数、可用积分；今天应完成扣除免做，挑战单列，避免跨天挑战混入每日分母。点击计数进入 P02，点击孩子进入 P12。

无孩子：引导添加孩子；有孩子无计划：显示「一起约定第一件小事」→ P04；无待办：「现在没有待办，看看今天的计划」。待兑现独立保留，即使已超过一周也不能从摘要消失。快捷代录首先选孩子、日期和真实适用实例；不直接发一个无来源的任务奖励。

### P02 待办

顶部三个分段「完成审核 / 兑换批准 / 奖励兑现」，数量各自来自服务端。默认显示从首页点入的分段，独立保留筛选；按待处理时间升序，兑换批准额外突出准确到期时间，不通过颜色表达唯一信息。字段包括孩子、活动/奖励名、实例日期/申请时间、固定积分/原订单价、状态、提交说明摘要。

点击进入 P06/P10 后单条处理；P0 没有批量批准。自己代录提交的记录正常出现且能审核。刚被其他家长处理的行显示最新结果后移出当前待办，提示操作者；下拉刷新不过滤掉截止后仍可审核的活动。空态「这一类待办都处理好了」，可切其他分段。

### P03 计划列表

顶部「日常 / 一次挑战」、孩子筛选、状态筛选和「新建计划」。日常卡显示每周安排、适用孩子、目标、积分、当前有效状态与次日生效改动；挑战卡显示准确起止、适用孩子、未开始/进行中/已结束/已停止。可以搜索名称，空搜索结果支持清除条件。

日常不以“今天适用”作为唯一默认列表，避免家长找不到星期一的计划；默认显示全部已发布及草稿日常，当前暂停也能管理。P0 计划不提供未定义的归档动作。新建先选类型，编辑不能把日常改成挑战。计划创建成功返回详情，列表刷新。

### P04 创建与编辑计划

| 字段 | 控件、校验、默认值 | 条件/交互 |
| --- | --- | --- |
| 类型 | 日常/一次挑战二选一 | 新建首步；保存后不可互换 |
| 名称 | 单行，2—40 字，必填 | 示例只给“整理书包”“跳绳”，不代填完成标准 |
| 完成要求 | 多行，0—500 字 | 解释如何确认，不提供统一强度建议 |
| 图标 | 内置图标选择器 | 默认通用活动，P0 无上传 |
| 计量方式 | 完成即可 / 次数 / 分钟 / 米 | COUNT/DURATION/DISTANCE 要求正整数目标；CHECK 无数值输入 |
| 达标值 | 数字键盘，显示固定单位；次/个 1—100,000，整分钟 1—1,440，整米 1—1,000,000 | 均为技术输入上限，非运动建议；未达标只可存草稿；一次达标固定发分，超额不额外加分 |
| 奖励积分 | 整数 1—1,000 | 标签「完成并通过后获得」，不使用价格货币符号 |

| 日常重复 | 每天 / 选择星期；至少一天 | 默认每天，周一至周日中文全称 |
| 新建日常生效 | 默认明天，可明确选今天 | 选今天提示「今天从发布时刻开始适用」，不回填凌晨任务 |
| 挑战窗口 | 日期+时间，明确北京时间 | 结束晚于开始；确认区完整复述窗口，结束时刻不包含在内 |

提交前固定预览句：「朵朵 · 每周一三五 · 达到 100 次 · 每次通过得 10 积分 · 明天起」。输入不合法时不丢其他字段；没有孩子时就地引导创建并恢复草稿。

已发布日常编辑、移除适用孩子、暂停/恢复一律次日生效；页面分开展示“今天仍按原约定”和“明天起的新约定”。计划完成详情永远显示实例快照。已发布挑战目标、积分、适用孩子和窗口只读；可以修改不改变完成要求的展示描述，或复制为新挑战。不得以“编辑描述”绕过冻结规则。

### P05 计划详情与完成情况

展示计划要求、版本生效信息、适用孩子、日常按业务日期选择/挑战按完整周期展示。日常默认今天，历史日期可浏览，未来日期为安排预览，不生成可审核结果；每个孩子均显示其适用实例，未曾打开的孩子同样在列表中。不适用日期显示「这一天还没有安排给朵朵」，不显示“未完成”。

孩子行显示状态、完成量、固定积分、补充截止时间（存在时）→ P06。日常操作「编辑明天起的计划」「暂停/恢复（明天生效）」；挑战「修改展示说明」「复制新挑战」「停止挑战」。停止确认解释：立即停止未提交的新提交，已提交仍可审核，已获补充期限保留，已得积分不退回。停止成功后页面保留历史与完整状态。

### P06 完成详情、审核与代录

顶部始终是孩子、活动类型、所属业务日期/挑战窗口、实例要求及积分快照。中部是本次总完成量、文字说明、0—3 张照片、提交人（孩子自己的账号/家长设备孩子会话/某家长代录）、历次提交/退回/通过事件。照片可点开鉴权大图，图片加载失败独立重试，不阻断文字阅读；已到 180 天清理显示原因而非坏图标。不得覆盖历史退回理由和旧提交照片。家长代录支持同样的可选照片上传组件。

| 实例状态/时间 | 主操作 | 辅助操作与文案 |
| --- | --- | --- |
| OPEN，允许操作窗口内 | 「记录完成并加 10 分」 | 输入真实完成量，说明选填；「今天休息/本次免做」原因必填 |
| SUBMITTED | 「通过并加 10 分」 | 「请补充」原因必填；可免做；同一代录家长可通过 |
| NEEDS_CHANGES | 「记录完成并加 10 分」 | 原退回原因和补充期限；可免做；孩子有独立补充入口 |
| APPROVED | 无再次提交/审核按钮 | 「查看积分记录」；有资格纠错时 → P14 完整撤销 |
| EXEMPTED | 只读「今天休息 / 本次免做」 | 展示原因与操作人；P0 无恢复按钮 |
| REVOKED | 只读「该次积分已撤销」 | 原通过和撤销记录都保留；不提供重新发同一奖励 |
| 逾期 OPEN/NEEDS_CHANGES，仍可家长补记 | 「补记完成并加 10 分」 | 显示真实适用日期和补记边界，不改成今天完成 |
| 超出补记时间/不存在历史适用实例 | 只读 | 「这次记录已超出补记范围」或「这一天没有此安排」 |

「通过」页面明确孩子、分值与依据，点击后原子入账，成功显示最新余额和通过人。「请补充」展示将生成的截止时间：原截止与本次退回后 24 小时中较晚者；成功后从待审核移出进入需补充。家长直接记录不需要制造一个只能由其他人审核的任务；若家长选择“代孩子提交等待审核”，则走与孩子相同的 SUBMITTED 流程，也允许其本人后续审核。

日常补记日期选择器允许今天及过去 7 个业务日，共 8 个日期；2026-09-19 操作时最早是 09-12，09-11 不可选。挑战截止后 7×24 小时内可补记，边界由服务端给出，在边界时刻停止接受。代录表单另填实际完成时间 `completedAt`，默认当前时间仅适用于当前仍开放实例；补历史时必须选原窗口内且不晚于现在的时间，界面分开展示“实际完成”和服务器“记录时间”。补记仍须真实适用实例，不允许为孩子加入/指派前新增任务。挑战实际开放不早于计划开始、发布/指派、孩子建档三者最大值；未开始实例不能提前完成。已停止挑战仅可补记停止前真实完成的结果，并标记“停止后补记”，操作仍须早于原截止+7×24小时。

免做确认「本次不计入应完成，也不会获得积分」，原因 1—200 字；不会删除已提交内容。已通过的纠错必须到原积分记录发起，不能编辑完成量或减少一部分积分。余额不足时留在只读详情，明确可用与所需数额，不建议随意取消孩子已承诺奖励来扣分。

### P07 奖励与订单

顶部「奖励库 / 兑换订单」分段；奖励库有上架/下架/草稿/归档筛选、名称搜索、类型筛选和「添加奖励」。卡片显示一份权益名称、价格、可用库存或不限量、适用孩子、周限额。订单页有待批准/待兑现/已兑现/已结束筛选和孩子选择，已结束含拒绝/取消/过期，详情保留各自原状态。

空奖励库引导添加一份明确权益，例如“游戏 20 分钟”；不能把游戏时间表述成自动限制屏幕的功能。订单无数据时显示「孩子申请奖励后会出现在这里」，不把管理员直接送奖励混入订单链路。点击奖励 P09；点击订单 P10。

### P08 奖励编辑与库存

字段：名称 2—40 字、内置图标、类型 TIME/FOOD/ITEM/EXPERIENCE、描述 0—500 字、一份权益说明 1—200 字、价格 1—100,000 正整数、适用孩子至少一人、每孩子每自然周兑换次数（不限或整数 1—100）、库存模式 FINITE/UNLIMITED。TIME 额外明确“一份共多少整分钟”，整数 1—1,440；食品写清楚一份是什么，物品写清款式或可接受范围，体验写清活动与安排方式。兑现说明应让家长和孩子能判断是否已交付。

有限库存输入初始可用数量（整数 0—1,000,000），不限量隐藏数量框。发布后库存模式只读；调库存使用独立入口，展示当前可用/已占用，输入非零整数增减及原因，负向调整不可使可用库存小于 0，新增补货需为待取消订单回库预留容量。不能直接用一个“剩余数量”输入覆盖并发占用。

保存草稿 / 上架均校验必要信息，上架前预览孩子端权益卡。编辑价格或限额提示「仅影响之后的新申请，已有订单按原约定」。上架至少有一名适用活跃孩子；有限库存为 0 可保存但孩子不能申请。存在相同名称时可提醒核对，不禁止不同规格奖励。

### P09 家长奖励详情

先呈现孩子会看到的完整权益，再显示管理区：编辑、上下架、库存调整、归档、历史订单。归档/下架阻止新申请，但保留订单办理。为孩子代申请时先选孩子，读该孩子可用积分、已预留、周剩余额度与奖励适用性，确认区和 C04 一致；不能使用成人身份建立积分订单。

确认后预留积分与库存，进入 P10「待批准」；家长本人可以继续批准，但不能把代申请按钮写成“立即兑换成功”。单家长无需邀请第二人。

### P10 家长兑换订单详情

首屏状态、孩子、一份权益名称与快照、原积分价；后续为申请/批准/兑现时间线、各阶段操作人、预留/扣分信息、原因与兑现说明。状态标签必须来自订单状态，不能只看余额。

| 状态 | 页面解释 | 可用操作 |
| --- | --- | --- |
| PENDING_APPROVAL | 「已为本次申请预留 30 积分，尚未花掉」；显示 72 小时批准截止 | 批准（将正式扣分）、拒绝（必填原因）、取消（必填原因） |
| READY | 「已花费 30 积分，等待家长按约定兑现」；不展示自动失效倒计时 | 「已实际兑现」与「取消并退回 30 积分」 |
| FULFILLED | 「已兑现」，实际交付说明与家长 | 只读；无取消/退款/再次兑现 |
| REJECTED | 拒绝原因、预留释放记录 | 查看账户，不能复活原订单 |
| CANCELED | 取消人/原因；批准前显示释放、批准后显示退款 | 只读，当前奖励仍可兑时可从奖励页另发新请求 |
| EXPIRED | 「72 小时内未批准，申请已过期」 | 显示释放结果；未清理时显示处理中并拉取真实余额 |

批准确认明确「批准后花费 30 积分，并承诺安排这份奖励」。兑现确认必须写「已经给了孩子约定的奖励」；TIME 示例为「已经提供约定的 20 分钟游戏时间」，输入交付说明选填，不启动计时、不拆分消费。按钮为「确认已兑现」，不得叫“领取”且批准不自动兑现。

取消 READY 确认「整单取消，退回原价 30 积分并恢复库存」，家长原因必填。取消后原申请周额度释放，不承诺增加当前周额度。并发取消/兑现只接受先成功的终态，另一端展示最新状态，绝不先本地退款。奖励下架、改价后此页照订单快照继续批准/兑现/取消。

### P11 家庭

从上到下为孩子列表及添加、共同家长、家庭约定说明、历史与操作记录、家庭设置。孩子卡只在家长模式显示多孩子；显示「进入孩子模式」入口但不以切换头像直接变成孩子。共同家长提示该身份有完整日常管理能力，邀请权限只由负责人提供。

### P12 孩子档案

新建/编辑字段为昵称 1—24 字、必填上传头像、可选年龄段（4 岁以下 / 4—6 / 7—9 / 10—12 / 13 岁及以上 / 不填写）；头像使用家长主动上传并验证成功的图片，格式/大小/裁剪与 S01 相同，不能以内置占位完成建档，不强制真人。上传失败保留昵称且禁止提交，编辑时原有效头像保留到新头像成功替换。不收集精确生日、学校、住址。孩子账户初始 0；不把成人余额迁移给孩子。已存在同名孩子时提示区别昵称，账号仍按 ID 区分。

账号绑定区显示「仅家长代操作」或已绑定账号头像/昵称。只有 OWNER 可点击「邀请孩子微信绑定」，生成 CHILD_BIND 邀请；待绑定与邀请到期时间可见，批准入口链接 P13。批准时并排显示原档案和申请者账号头像昵称，明确目标孩子，可选「同步账号头像昵称到孩子档案」，默认不自动覆盖；历史快照不改写。已绑定不显示直接换绑输入，须 OWNER「解除当前微信绑定」确认：旧账号 DIRECT 访问立即失效，账本/历史保留，家长可继续代操作，然后才可发新邀请。

详情显示可用/预留、当前心愿、完成记录、积分账本、「记录完成」「手动表扬」「进入孩子模式」「编辑档案」。归档入口放更多菜单，先请求预检：逐项列出 SUBMITTED/NEEDS_CHANGES 与 PENDING_APPROVAL/READY 待处理，提供跳转处理；不自动批准或取消。存在余额时复述「保留只读账本：可用 X、预留 Y」，明确确认后才归档；预留非零通常意味着订单未处理，应先阻止。归档成功撤销该孩子会话，档案只读，P0 无恢复按钮。

### P13 家长与邀请

成人列表显示已上传头像、称呼、角色、加入时间，不展示其微信号或手机号。OWNER 看「邀请家长」「入会申请」「移除」「转让负责人」；GUARDIAN 只读成员与「退出这个家庭」。邀请页解释共同家长权限，点击生成后提供复制邀请链接、微信原生分享以及立即撤销；24 小时有效、一次成功入会有效，具体到期时间常显。

待办分「成人加入申请」「孩子账号绑定」两个明确用途的分组；CHILD_BIND 审批卡显示目标孩子与申请账号上传头像、昵称、时间，拒绝可填原因，批准前再次核对未绑、未冲突、邀请仍有效。成人邀请不能绑定孩子，孩子邀请不能加入成家长。申请人撤回后卡片更新为只读，不能继续批准；两个负责人窗口重复批准只会绑定一次。

申请处理页显示申请者自填称呼、申请时间与来源邀请，批准/拒绝后给结果；批准时邀请仍须在 24 小时内有效、未撤销、未使用。同一邀请出现多个申请时只有第一条成功批准能入会，其他申请显示邀请已失效并需新的邀请。移除成人确认说明其家庭访问和派生孩子会话立即失效；转让先选现有共同家长，再明确确认新旧角色变化，不能转给孩子或待加入者。负责人退出必须先转让；最后一名成人显示「需要先处理家庭归档」，不能留下无成人家庭。退出/移除成功跳 S02，不留敏感缓存。

### P14 积分账本与表扬

顶部明确可用、申请预留、总持有=二者之和；筛选「全部 / 赚取 / 兑换 / 预留与释放 / 纠错与退款」。流水按时间倒序，条目显示动作、可用变化、预留变化、结果余额、来源、操作人、日期。预留显示「30 积分转为申请预留」，不把它标记成收入/消费；批准显示「兑换支出 30」，可用可能不再次变化，仍正确体现正式支出。

「手动表扬」显示孩子、整数 1—1,000、必填原因 1—200 字；确认后一次到账，账户持有上限冲突解释无法入账并保留表单。没有“扣积分”“惩罚”“调整为任意余额”入口。

合资格赚取记录详情提供「纠正这次记录」，输入原因后确认全额撤销；显示将撤销数与可用余额，不允许部分撤销、重复撤销、撤销订单扣分。活动奖励撤销后原实例变 REVOKED。余额不足显示明确缺口并关闭确认，原记录保持不变。退款和撤销各有独立关联行，不修改/删除原流水。

### P15 历史与操作记录

分为「完成记录 / 兑换记录 / 操作记录」，可按孩子、日期范围、类型/状态筛选；审计额外按操作者。数据分页，支持查看详情和来源跳转。默认近 30 日只是筛选默认，不是数据保留承诺；可选择更早范围。所有时间显示北京时间，发生日期与提交时间分别标注。

审计详情包含动作、操作者、对象、原因、前后业务状态、请求号；敏感令牌与 PIN 不进入展示。不提供删除流水/删除审计。归档家庭只能浏览已有记录和合法隐私申请状态，不再出现创建、表扬等按钮。

### P16 设置、隐私与生命周期

设置包含本人账号头像昵称、家庭名、家长 PIN、安全说明、隐私政策、个人数据申请、家庭数据导出申请、家庭数据删除申请、归档家庭。所有家长可以修改本人账号资料（头像上传规则同 S01，不能清空头像/昵称），并申请自己的个人数据处理；OWNER 额外可修改家庭级设置、提交家庭全量导出/删除申请与归档；GUARDIAN 可设置本人 PIN/安全项并退出，不能替家庭申请全量导出/删除。账号资料与家庭设置用独立标题区分，避免误把昵称修改成孩子档案修改。

导出和删除分独立流程：先说明范围与处理方式，提交后有申请编号、状态、提交时间、下一步和预计处理说明；所有处理方式/期限按技术文档，不得用一个“已删除” toast 代替后台实际完成。导出文件入口有有效期与访问校验，不自动转发给第三人。删除确认使用家庭名称核对，明确其范围；归档说明为保留只读，不能表述成删除。

家庭归档先列全部孩子未处理完成/订单并逐条跳转，全部清理后再确认；成功所有业务只读并撤销孩子会话。无权限的成人不显示危险动作；重新加载时 OWNER 已变更必须停止原表单。

## 6. 孩子页面详细规格

### C01 今天

顶部为孩子已上传档案头像和昵称；DELEGATED 显示「家长入口」，DIRECT 显示「账号设置」，两者以次级文字标明来源。问候短句、北京时间日期和可用积分保持一致。列表先放需要补充的事项，再放今天未完成日常和进行中挑战，已提交/已通过折叠但可展开。每卡含图标、名称、完成要求摘要、日常/挑战标签、固定积分与一个主动作。不出现“领取任务”前置步骤。

空态分三类：「今天还没有安排，和家长一起商量吧」「今天已经完成啦」「今天休息，明天再来」。不得用“落后”“失败”“断签”提示未完成。挑战显示截止日期和时间，临近截止只给事实；需要补充的旧任务保持独立提示，不混为今天日常。

### C02 活动详情与提交

详情标题是具体行动，例如「跳绳 100 次」，下方显示「达到目标，通过后得 10 积分」和完整说明。CHECK 为「我已经完成」确认；COUNT/DURATION/DISTANCE 为数字输入 + 固定单位，显示「填写这次的总数，不会把多次提交相加」。说明选填 0—200 字，下方是「完成照片（选填，0/3）」及「拍照 / 从相册选择」，无自动识别或计时器入口。

选图只在用户主动操作后请求相机/相册能力；拒绝授权或取消选择不丢次数和文字，仍可无图完成。单张上限 10 MiB、4,000 万像素，支持 JPEG/PNG/WebP；每张缩略图独立显示上传中进度、处理中、可用或失败，失败原因具体到过大/格式错误/网络问题。支持逐张重试和移除，最多 3 张；所有保留照片都 READY 后才可提交。上传成功不等于活动已提交，发送的是服务端媒体 ID，不接受外站 URL。

上传区固定提示「仅本家庭有权家长与本人可看；草稿照片保留 24 小时，首次正式提交后保留 180 天」。服务端去除 EXIF/GPS、最长边缩至 1600 px，原图不长期保留。已提交照片只读，退回补充使用新提交版本，旧照片保留其历史关联；引用旧图不延长首次提交后的 180 天。到期图片显示「照片已按保存期限清理」，草稿图上传后满 24 小时失效显示「草稿照片已过期，请重选或移除」，不能把失效媒体 ID 再提交。

未达标时按钮为「保存草稿」，提示「可以先记下来，完成后再提交」，不扣分。未发送输入标记“本地未同步”，显式保存成功才显示“草稿已保存”并存服务端；草稿按实例隔离且不发分。达标后按钮「提交给家长」；超额仍显示同一奖励。成功是「已经告诉家长啦，确认后积分会到账」，不是“获得积分”。在等待审核期间数字、说明和照片只读。

退回后页面置顶「再补充一下」与家长完整原因、准确补充期限，允许改同一实例总数/说明再次提交。超过补充期限显示「请家长帮忙看看」，不默认创建新实例。已通过显示「完成啦 · +10 积分」和可用余额；免做显示「今天休息」及原因；撤销显示「家长更正了这次记录」并可看原因，不说“处罚”。

截止跨越输入过程时，发送仍由服务端判定；被拒绝保留草稿、显示准确原因。新一天返回 C01 查询新实例，不把昨天草稿自动转为今天。草稿绑定家庭+孩子+实例，切换孩子/退出会话清理或隔离，不交给另一孩子。

### C03 心愿

首块是可选的一个当前心愿：名称、一份权益、当前可用积分/当前价格、进度、还差多少。没有心愿显示「选一个想努力换到的奖励」，仍可浏览全部。设心愿不预留积分和库存；换心愿需解释替换当前目标，申请兑换与设心愿是两个独立按钮。

中部「我的兑换」显示待批准/待兑现数→ C05，保证已经申请的奖励易找；下部奖励目录按类型筛选。卡片显示名称、价格、适用与库存状态。积分不够仍允许看详情和设心愿；下架的心愿保留名称与「暂时不能兑换」，允许换目标，进度不能用旧价格计算。

### C04 奖励详情与申请

顶部明确一份奖励，例如「游戏 20 分钟 · 一次使用」；正文说明由家长安排，系统不计时、不控制设备。可用积分、已预留积分、价格、有限库存剩余、本人本周可申请次数一并展示；不限量/不限次数显示文字，不能用一个假大整数代替。

点击「申请这份奖励」进入同页确认面板：奖励、数量一份、原价、申请后可用余额、预留余额变化和「需要家长同意，72 小时内未批准会自动释放」。最终按钮「预留 30 积分并申请」。不足、售罄、限额、下架、非适用等原因在按钮附近展示，不只靠灰色按钮；可用时「设为心愿」独立存在。

提交成功进入 C05 PENDING_APPROVAL，余额按服务端更新。价格/版本变了要重新展示新信息与确认，不能按新价格静默继续；即使积分足够也必须确认。库存/限额争抢失败不产生订单和预留，回到可解释状态。网络结果未明走 S04，不弹“再试一次兑换”。

### C05 我的兑换与详情

列表分「等家长同意 / 等待兑现 / 以前的兑换」，显示一份权益、申请日期、状态；待兑现永远独立可找，不随跨周自动消失。详情与家长端共用快照及时间线，但没有批准或兑现按钮。

待批准文案「积分先帮你留好了，等家长同意」；待兑现「家长同意啦，一起安排什么时候兑现吧」；已兑现「这份奖励已兑现」；拒绝显示家长原因及已释放；过期解释家长尚未处理并核实释放状态。孩子可取消待批准或待兑现订单，确认选预设理由「暂时不想要了 / 想换别的 / 和家长商量后取消」，展示释放或退款后果；没有批量取消。

72 小时边界到达而释放尚未完成时显示「申请已到期，积分正在释放」和刷新动作，当前可用保持服务端值。取消结果与家长兑现冲突时，最新已兑现页面替换取消面板；不误报退款。

### C06 成长

顶部显示本人可用积分及申请预留，随后是「本周完成」「本周赚取」等具有明确周期的个人信息，不与其他孩子比较。周一 00:00 为周起点；周赚取仅活动/手动表扬，退款/预留/释放/撤销独立列示。日常与挑战可分别查看，不做含义不明的总体“完成率”。

完成历史按业务日期/挑战周期，积分明细按入账时间；每条都可以展开查看来源、原因、家长称呼与结果及未到保存期限的照片。列表空态「每一次努力，都可以在这里看到」，无排行榜或惩罚提醒。孩子只看到自己的记录，不能看到家庭全部审计。

DIRECT 的「我的账号与隐私」子页提供本人微信账号头像昵称修改、本人账号退出、隐私说明、个人数据导出/删除申请及进度。头像与昵称始终有效才能保存，新头像失败时保留原有效头像；改账号资料不会静默覆盖家庭档案历史。个人申请明确不等于全家数据申请，范围与期限读技术分册。DELEGATED 不显示此入口，也不能借直接路由访问源家长头像昵称、隐私申请和账号设置。DIRECT 被解绑后只剩仍合法的账号/其他上下文入口，立即移除原孩子及图片缓存。

## 7. 关键逐步流程与验收路径

### 7.1 一位家长建立首个闭环

1. S01 微信登录，确认隐私；S01b 上传头像并填写“妈妈”，资料成功保存后 S02 创建“向日葵之家”。
2. P12 新建“朵朵”，家长上传孩子档案头像，年龄段可跳过。账户为 0。
3. P04 建日常「跳绳」，COUNT 100 次，10 积分，适用朵朵；家长明确选择今天开始。示例数字仅演示家庭约定，不是运动建议。
4. P08 建「游戏 20 分钟」，30 积分，不限量、每自然周 2 次，权益“家长安排，一次提供 20 分钟”，上架。
5. P06 在真实完成后直接记录并加分；同一家长也可以代提交，再在 P02 自己审核。两种路径各产生一次入账，不能叠加。
6. 累积足够积分后 P09 为朵朵申请，进入待批准；同一家长在 P10 批准，积分从预留转正式支出；实际提供奖励后再确认兑现。

### 7.2 孩子提交 → 家长审核 → 申请 → 批准 → 兑现

1. 全部使用者先完成微信登录和必填上传头像/昵称。DELEGATED 由家长 S03 设置 PIN、保存恢复码、选择朵朵进入；DIRECT 则由孩子本人账号经绑定批准进入。演示起始可用 20、预留 0。
2. C01 点跳绳 → C02 输入 100 次，可选 0—3 张照片并等待处理完成 → 提交：状态 SUBMITTED，仍可用 20。
3. DELEGATED 家长入口 → PIN 验证；若为 DIRECT，则另由合法家长微信账号登录处理，孩子账号不通过 PIN 升权。P02 查看数量、文字和照片后通过：状态 APPROVED，可用 30、预留 0。
4. 再进入朵朵孩子模式，C03 → C04 游戏 20 分钟，申请 30 积分：订单 PENDING_APPROVAL，可用 0、预留 30，总持有 30。
5. 家长 PIN 验证 → P10 批准：READY，可用 0、预留 0；本次正式支出 30。
6. 线下提供完约定奖励 → P10「确认已兑现」：FULFILLED，无二次积分或库存变化。孩子 C05 可看到兑现记录。

### 7.3 退回、补充与休息

家长在原 SUBMITTED 详情填具体原因，例如“请补充这次完成的总次数” → 退回后按服务器给出的补充截止展示 → 孩子在期限前改同一记录并提交 → 家长一次审核发分。若选择休息，家长填原因设 EXEMPTED，不发分、移出应完成数，不恢复也不建立一个同日替身任务。

### 7.4 取消与兑现的区别

PENDING_APPROVAL 取消释放原预留；READY 取消退回原价；两者都恢复一份有限库存和原申请周额度，均有原因和记录。FULFILLED 表示实际交付完成，不能取消或退款。奖励尚未交付时不要为了“清待办”点兑现；产品提示应直接解释这个事实。

### 7.5 次日变更及补记

家长今天改跳绳目标，今日实例仍按原值；明日及以后按新生效版本生成。今天选择昨天补记时，详情读取昨天的目标与分值，不读当前计划值。超过 7 个过去业务日不开放补记；孩子加入前不产生“漏做”。

### 7.6 跨家长并发及未知结果

两位家长同时批准活动，只能一个发分；另一位刷新看到同一结果。孩子申请超时后重启，先查询原操作定位原订单；家长随后批准该订单仍只花一次积分。若请求始终未确认，显示请求号和恢复入口，不能通过更换家庭或进入孩子模式丢失追踪。

## 8. 时间、状态与金额显示细则

| 业务边界 | UI 应显示 | 操作判定 |
| --- | --- | --- |
| 日常 23:59 → 00:00 | 当日标签变更，旧实例标示日期 | 新提交按服务端时刻，旧日不能当新日发分 |
| 挑战 startsAt | 由“尚未开始”变为“进行中” | 左边界允许；先刷新服务端资格 |
| 挑战 endsAt | “已结束” | 右边界不允许新提交；已提交继续审核 |
| NEEDS_CHANGES 截止 | 显示绝对日期时间；不只写“明天前” | `max(原截止, 本次退回+24小时)` |
| 日常补记 | 可选今天和过去 7 日 | 真实历史适用实例且仍处可补记状态 |
| 挑战补记边界 | 显示最后接受时间 | 截止后 7×24 小时内；恰到边界禁止 |
| 订单 72 小时 | 显示批准到期时间 | 到期禁止批准；释放处理中不虚增可用 |
| 自然周更换 | 本周额度重读 | 旧订单仍占原申请周，不挪到新周 |
| 日常变更 | 明天起生效 | 今日快照不变；新孩子不追补历史 |

积分不带小数，不加 ¥，数值旁有「积分」。余额未知显示「—」和加载/失败状态，0 是合法真实余额。进度条上限 100%，可用积分超过心愿价格仍保留实际数字，屏幕阅读文本写“已攒够，可以申请”，不只读百分比。

## 9. 文案与交互验收

| 情境 | 推荐文案 | 验收要点 |
| --- | --- | --- |
| 完成提交成功 | 已经告诉家长啦，确认后积分会到账 | 未提前发分 |
| 退回 | 再补充一下：{原因} | 不称“失败”；期限可见 |
| 申请成功 | 已预留 {n} 积分，等家长同意 | 可用与预留同时刷新 |
| 批准成功 | 已批准，请安排兑现这份奖励 | 不称“已兑现” |
| 兑现确认 | 已经提供了约定奖励吗？ | 无默认计时，无部分兑现 |
| 奖励变价 | 奖励已更新，请查看后再确认 | 不静默接受新价格 |
| 无网未知 | 结果尚未确认，我们会查询这次操作 | 原 key 保留 |
| 休息 | 今天休息，不影响积分 | 不扣分、不计应完成 |
| 撤销 | 家长更正了这次记录：{原因} | 只纠错，不出现任意惩罚入口 |

交互验收至少覆盖：强制上传头像与昵称（半完成/失败/重启/深链拦截）；单家长全部闭环；DIRECT 绑定/解绑/同家庭角色冲突；DIRECT 不能 PIN 升权；DELEGATED 不能访问源成人账号；同名多孩子不串档；成人被移除后旧链接失效；孩子回退/重启/PIN 错误不能进入成人页；照片拒绝授权/失败重试/移除/过期/越权；申请时先预留、批准时支出；申请与取消/兑现并发；72 小时清理延迟；次日变更；7 日补记；挑战停止后的补充与真实补记；免做后的统计；余额不足撤销；归档前待处理拦截；长文案/小屏/键盘；读失败与空态区分；重启后恢复未知结果。
