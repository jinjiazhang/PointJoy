版本：1.0 · 日期：2026-09-19 · 语言：中文。

这是一套独立的重建规格，用于把现有“群组积分”小程序重新设计为家庭场景：孩子完成日常、跳绳、跑步等约定，获得积分，再申请游戏时间、冰淇淋、薯条等家庭奖励，由家长批准并兑现。

**已按最新要求纳入：必须微信登录，首次必须上传头像并填写昵称；孩子可用自己的微信登录，家长也可代办；完成时支持可选照片。** 新文档不要求沿用原有页面结构、数据库或“不能审核自己”规则。

本包是拟实现的产品、交互和工程规格，附可点击页面示意；不表示这些新功能已经开发上线。本次未修改原业务代码、现网或数据库。

## 关键设计决策

- **家庭和孩子档案为业务主体。** 微信账号负责登录，孩子档案负责积分和历史。孩子自己登录与家长代办访问同一档案，避免两个余额。
- **强制头像昵称关卡。** 先登录、上传头像并填昵称，服务端确认后才放行业务；不是前端跳转约定。头像可以是自选图片，不要求真人脸或实名。
- **两套清晰导航。** 家长：首页/计划/奖励/家庭；孩子：今天/心愿/成长。日常与挑战保留不同周期，在同一个使用视角呈现。
- **不先领取，达标后提交。** 支持勾选、次数、分钟、米；可附照片，家长审核后一次发分。家长可以直接记录真实完成，也可有限补记或本次免做。
- **申请、批准、兑现分开。** 申请预留积分，批准正式消费，实际提供后确认兑现；未兑现取消全额返还，72小时未批准自动释放。
- **把孩子模式和权限做在服务端。** 孩子自己登录与家长设备的受限模式分开，后者才可用源家长PIN退出，不能通过重启或重新微信登录升权。
- **保留可解释账目。** 积分、库存、周次数、状态和审计同事务，错误纠正追加记录，不改旧账、不制造负余额。

## 范围与交付要求

P0是完整首发范围，包括微信登录、强制资料、孩子账号绑定、图片上传、家庭与成员、计划、完成审核、积分、奖励、兑现、历史、隐私申请和运维验收。P1不是首发入口：自定义奖励封面、持续计时/部分权益消费、周期累计目标、批量审核、订阅消息、归档恢复。

预览是文档配套的本地演示，没有微信登录、真实上传、后台、持久账本或生产权限保护。演示中的数据、PIN和图片不用于生产。详细范围和操作说明见设计文档；原型未演示的页面仍须按交互文档实现。

规则冲突应在开发前修订同一版本：00为统一业务基线，02负责需求和范围，03/04负责呈现，05/06负责落地，07负责验收。不能用原型简化逻辑覆盖业务规则，也不能以旧代码已经能跑代替新设计验收。
