# 积乐圈家庭版：产品需求文档（PRD）

版本：1.0 · 2026-09-19 · 状态：待实现、待验收。

用户最新确认已纳入：**所有使用者必须微信登录；首次必须上传头像、填写昵称；孩子可以独立微信登录，也可由家长代办；完成提交可以附照片。** 本文和 [00-规则基线](00-规则基线.md) 定义首发范围。页面编号见 [03-交互文档](03-交互文档.md)，接口契约见 [06-技术文档](06-技术文档.md)。

## 1. 目标、假设与发布范围

### 1.1 必须解决的问题

1. 约定不清：把具体行为、达标条件、适用孩子、发生时间和奖励积分写清楚。
2. 操作麻烦：孩子不用先领取；单家长可以直接记录已完成；日常和挑战在一个任务视角出现。
3. 等待无反馈：孩子能看到待审核、需补充、申请中、家长已批准和已兑现的区别。
4. 奖励难兑现：明确一份权益、家长批准、实际交付、未兑现可退、待办提醒。
5. 账目不可信：每次发分、预留、消费和返还可追溯，重复请求和同时操作不重记。
6. 身份混淆：一个孩子一个家庭账本；个人微信绑定与家长代办操作共享同一档案，不能建成两套余额。

### 1.2 首发约束

面向私人家庭、中文、微信小程序，固定北京时间业务日。约 4—12 岁是设计人群假设，不限制其他年龄，也不推导医学运动标准。首发不提供支付、充值、提现、公开排行、定位识别、自动运动判断、广告及游戏应用控制。

P0 表示首发必须交付，不等同于“只有主流程”。失败恢复、头像/照片权限、数据导出删除、归档和账务对账均属于 P0。P1：自定义奖励封面、持续计时/部分使用、周期累计目标、批量审核、订阅消息、归档恢复。

新项目默认新建数据库。旧数据是否迁移、由谁映射孩子、如何处理旧余额须另立实施方案；本次不授权清空或更改现网。

## 4. 首次使用、身份与资料规则

### 4.1 强制资料流程

微信登录建立受限资料会话 → 读取公开隐私说明与资料状态 → 选择/拍摄头像、填写昵称 → 上传并等待处理成功 → 保存头像媒体 ID 与昵称 → 服务端校验并设置完成标记 → 按已有关系进入家庭。

头像与昵称两者都有效才能完成。上传成功但资料保存失败，不放行；重复保存原请求不创建第二个账号。头像可为用户自选插画或照片，不强制真人自拍，默认占位图片不能通关。昵称不要求实名。

已经完成资料的用户再次登录只检查状态，不要求每次更换。头像媒体被判定不可用或清理时不得继续用一个伪完成标记，应提示补充；账号当前使用的头像不适用未关联上传清理规则。

设过家长 PIN 的账号新微信登录先 LOCKED，PIN 通过后仍要检查资料是否完整。未设 PIN 的新账号先完成资料，完成家庭配置即可；第一次切孩子模式前设置 PIN。不能先取得管理权限再在前端遮住资料页。

### 4.2 孩子账号绑定

负责人从已有孩子档案创建专属邀请 → 孩子微信登录并完整资料 → 查看最少邀请说明并申请 → 负责人核对账号头像昵称与目标孩子 → 确认绑定 → 孩子进入自己的今天页。

绑定必须同时满足：家庭/孩子有效、邀请仍在 24 小时内且未使用/撤销、孩子尚未绑定、账号在本家庭没有家长关系和其他孩子绑定。请求里替换孩子 ID 无效，目标只从邀请读。审批与唯一绑定写入同事务。

换绑不能直接覆盖；先解绑，旧账号立即失去孩子内容和图片读取权限，再发新邀请。原孩子账户和全部历史保留，审核操作人不改写。解绑不代表注销微信账号；其他家庭的合法关系不变。错误申请可拒绝或撤回。

DIRECT 账号在自己的设置中可以修改自己的头像昵称、退出登录、查看隐私与申请个人数据处理；不能查看源家长账号。DELEGATED 模式不能修改家长资料，也不能以“重新登录”恢复家长权限。

### 4.3 输入规范

长度按 Unicode 字符计、去首尾空白；纯空白无效，不以 UTF-8 字节数直接限制中文。输入文本按纯文本渲染。

| 字段 | 必填与范围 | 备注 |
| --- | --- | --- |
| 账号昵称 / 孩子昵称 | 1—24 字 | 不强制实名；昵称重复不合并身份 |
| 账号头像 / 新孩子档案头像 | 有效用户上传媒体 | 512×512 输出；不允许占位或外站 URL |
| 家庭名称 | 2—30 字 | 不要求唯一 |
| 年龄段 | 选填 | 4岁以下/4—6/7—9/10—12/13岁及以上；不收精确生日 |
| 计划/奖励名称 | 2—40 字 | 同名可提醒，不以名称唯一约束 |
| 计划/奖励描述 | 0—500 字 | 达标标准仍有结构化字段 |
| 完成说明 | 0—200 字 | 可不填，不强制写心得 |
| 退回/拒绝/免做/表扬/撤销原因 | 1—200 字 | 不用空白或只有空格的默认值替代 |
| 一份奖励权益描述 | 1—200 字 | 说清数量、安排和内容 |
| 单次发分 | 整数 1—1,000 | 不支持小数和负发分 |
| 奖励价格 | 整数 1—100,000 | 免费家庭活动不建零价积分奖励 |
| COUNT 目标/实际值 | 目标 1—100,000；草稿实际值可为 0 | 达标提交至少目标值，最大同技术上限 |
| DURATION 目标/实际值 | 目标 1—1,440 整分钟 | 同上；不接受 1.5 分钟浮点 |
| DISTANCE 目标/实际值 | 目标 1—1,000,000 整米 | UI 标单位；存储统一米 |

上述数量仅为技术输入范围，不表示适合儿童的强度或使用时长。默认示例可修改，不按年龄自动生成“必须完成”的指标。

## 5. 计划与发生实例规则

### 5.1 日常

家长至少选择一名活跃孩子、一个星期日以及一种达成方式。创建草稿不会产生应完成任务；发布后默认明天起，在确认页主动选今天则从提交成功时开始。频率使用星期一至日，不使用“每 24 小时”推算自然日。

ROUTINE 每个计划/孩子/业务日期只有一个实例，即使重复发布、刷新、多个客户端或后台同时生成也相同。规则快照按当日有效版本取值，包含名称、达成方式、目标、积分、起止窗口和适用孩子。

已发布日常修改目标、积分、星期、移除适用孩子、暂停和恢复均在次日 00:00 生效。今日实例保持旧版本。对尚未生效的明日排程再改，形成新的修订并保留审计；同一时刻只有一个有效版本。首发不提前物化未来已承诺实例，未来排程仅作预览。

今日创建孩子或加入适用集合不会追补历史日期；暂停日不生成“欠做”，恢复也不补暂停期间。统计必须按历史版本的完整适用集合计算，不因某天没人打开小程序而遗漏分母。

### 5.2 一次挑战

发布时固定适用孩子、目标、积分、开始/结束时间。结束必须晚于开始且晚于发布时刻；允许活动已开始但尚未截止，此时新实例开放时间不得早于该孩子的真实指派时刻。

每个计划/孩子全周期一个实例，不以日期或版本再建一条。展示说明可更新，但不得修改达标标准；发布后如需改标准，复制为新挑战。新挑战是独立约定，确认页提示会形成新的可获奖机会，避免误点复制重复奖励。

停止后 OPEN 不再接受孩子新提交，SUBMITTED 仍能审核，NEEDS_CHANGES 按原补充权利继续。APPROVED 积分不撤回。家长对停止前真实完成的结果仍可有限补记，必须记录实际完成时间早于停止时间。

### 5.3 状态机

| 当前状态 | 动作与条件 | 结果 | 积分 |
| --- | --- | --- | --- |
| OPEN | 孩子在窗口内提交达标值，照片均 READY | SUBMITTED | 无 |
| OPEN / NEEDS_CHANGES | 保存草稿 | 原状态 | 无 |
| SUBMITTED | 家长审核通过 | APPROVED | 固定积分快照到账一次 |
| SUBMITTED | 家长说明原因退回 | NEEDS_CHANGES | 无 |
| NEEDS_CHANGES | 在补充期限内提交达标内容 | SUBMITTED | 无 |
| OPEN / NEEDS_CHANGES | 家长合法代录/补记 | APPROVED | 固定积分快照到账一次 |
| OPEN / SUBMITTED / NEEDS_CHANGES | 家长说明原因免做 | EXEMPTED | 无 |
| APPROVED | 原发奖完整撤销，余额足够 | REVOKED | 扣回原数一次 |
| EXEMPTED / REVOKED | 尝试重新提交/发奖 | 拒绝 | 无 |

未开始、未记录逾期、补充逾期、挑战已停止是派生显示条件，不把数据库状态随时钟反复改写。已通过不可编辑结果；需要表扬新的真实行为用手动表扬，不能恢复旧实例再自动发奖。

### 5.4 时间边界

| 情形 | 精确规则 |
| --- | --- |
| 时区 | Asia/Shanghai；服务端时钟；业务日单独存 DATE，时间戳存 UTC |
| 日常新提交 | `startsAt <= now < endsAt`；普通完整日是当地 [00:00, 次日00:00) |
| 挑战新提交 | 同左，且未停止；按原唯一实例 |
| 补充截止 | `max(原endsAt, 本次returnedAt + 24小时)`；now 等于截止即不允许 |
| 审核 | 截止前合法提交的记录，后续仍可审核；无自动批准 |
| 日常家长补记 | `today-7 <= occurrenceDate <= today`；如今天9月19日，可补9月12日，不可补9月11日 |
| 挑战家长补记 | 操作 `now < endsAt + 7×24小时`；边界相等不允许 |
| 代录实际时间 | `startsAt <= completedAt < endsAt` 且 `completedAt <= now`；已停止挑战另要求 `completedAt < stoppedAt` |
| 记录时间 | `recordedAt` 由服务端生成，不接受用完成时间替换审计时间 |

### 5.5 草稿与照片

不达标只能存草稿；数值是本实例的总完成量，不自动累加多次输入。未发送输入暂存本地并标记未同步，显式保存成功后存服务端草稿。草稿按家庭/孩子/实例隔离，不自动挪到次日任务。

完成照片 0—3 张，每张原文件 ≤10 MiB、≤4,000万像素，JPEG/PNG/WebP；客户端检查帮助反馈，服务端检查才是准入。头像和完成照片用途不可互换，不接受其他孩子或家庭媒体 ID。

图片完成服务端重编码、清理 EXIF/GPS 后才是 READY。保留照片上传失败时禁止提交，移除失败照片后可无图提交。已提交媒体不被新上传直接覆盖；退回补充生成新的 submission，旧版可审计。照片自首次正式提交起保留180天，再次引用不延期；未正式提交的照片（含草稿引用）自上传起24小时清理，到期需重选，界面提前说明。到期删除不删积分事实；读取显示清理原因，不用损坏图标代替说明。正在使用的头像不采用这些完成照片期限。

不强制打开相机和相册权限，用户拒绝授权仍可无图完成。相机/相册访问由主动操作触发；头像无法取得文件时停在资料页并保留昵称，不能绕过必填头像。

## 6. 积分与统计需求

### 6.1 积分记账

用 A 表示可用，H 表示预留，p 表示本次积分。

| 操作 | A 变化 | H 变化 | 收支展示 |
| --- | --- | --- | --- |
| 活动认可/手动表扬 | +p | 0 | 赚取 |
| 请求奖励 | −p | +p | 预留，不算消费 |
| 家长批准 | 0 | −p | 兑换支出 |
| 请求被拒绝/取消/过期 | +p | −p | 预留释放，不算收入 |
| 已批准未兑现取消 | +p | 0 | 退款，不算赚取 |
| 已提供奖励确认兑现 | 0 | 0 | 不重复消费 |
| 原错误发奖完整撤销 | −p | 0 | 撤销，不伪装兑换消费 |

所有账户从0开始，有同事务不可修改流水，保存前后结果、来源、操作人和版本。任何失败不得留下半条账。负余额、负预留均禁止。

新增发奖准入检查 `A + H + p <= 1,000,000`。原价退款和预留释放不可因这个阈值失败；退款后可以暂时超出1,000,000，此时暂停新发奖直到准入条件成立。撤销只动可用积分，不能挪用申请预留或自动取消其他订单。

### 6.2 展示与统计口径

- 今日完成：该孩子该日期 APPROVED 日常数；应完成：历史适用日常实例数减 EXEMPTED；REVOKED 不计完成但仍计应完成。分母0不显示0%失败，显示无安排。
- 今天待审：当日实例 SUBMITTED 数；首页全部待审还包括历史仍待审记录，两者标题区分。
- 挑战：按未开始、进行中、待审、需补充、已通过、免做、已停止/截止未记录单列状态数量，不与日常混合成完成率。
- 积分收入按入账时刻归属；完成统计按任务发生日期归属，晚审核可以更新过去日期的完成情况。
- 赚取=活动奖励+手动表扬；净赚取另减错误发奖撤销。兑换支出=批准扣款，净支出另减订单退款。预留/释放均不计入收入或消费。
- 当前心愿进度=`min(A/当前价格,1)`；差额=`max(当前价格-A,0)`，不能把H也算可消费。
- 不跨孩子合并成家庭可花余额，不出现公开或兄弟姐妹排名。

## 7. 奖励、库存和订单需求

### 7.1 奖励发布

分类为 TIME/FOOD/ITEM/EXPERIENCE；每份权益必须明确。TIME 增加整数 timeMinutes，说明提供方式；只是家庭约定，不保证系统控制游戏或持续计时。

状态 DRAFT/ACTIVE/INACTIVE/ARCHIVED：草稿编辑，发布上架，临时下架可重上，归档只读且首发不恢复。已有订单始终可办理，不能靠下架取消家长承诺。

有限库存 FINITE 和不限库存 UNLIMITED 发布后不可互改；数量每单固定1。价格、名称、说明和孩子范围可修改，只影响新请求；所有旧订单保留快照。有限库存调整必须有原因，不能为负；技术容量检查须为待取消订单归还留出空间。

### 7.2 周次数与适用范围

每个奖励可选每孩子每周次数上限，周一当地00:00开始。额度按 `(family, reward, child, requestWeekStart)` 独立计算。有效占用订单为 PENDING_APPROVAL、READY、FULFILLED。

孩子周日发起、周一批准仍占上周；拒绝、申请到期或未兑现取消释放原申请周。已兑现永久占其原申请周次数。修改每周上限不影响已存在订单，已有占用大于新上限时仅禁止新请求，不撤销已有订单。

更换孩子适用范围后，移除孩子不能再申请，但已有订单仍有效。孩子归档/家庭归档是生命周期权限限制，不能通过旧订单绕过归档只读。

### 7.3 状态转换与取消

| 当前 | 动作 | 下一状态 | 必须同时完成 |
| --- | --- | --- | --- |
| 无 | 合法申请 | PENDING_APPROVAL | 保存快照，A→H，有限库存−1，原周额度+1，72h截止 |
| PENDING_APPROVAL | 家长批准且未到期 | READY | H正式扣除，记录批准成人及可选安排 |
| PENDING_APPROVAL | 家长拒绝 | REJECTED | 释放H到A、回库、释放原周额度、原因 |
| PENDING_APPROVAL | 孩子/家长取消 | CANCELED | 同上；孩子预设理由可用 |
| PENDING_APPROVAL | now到达72h截止 | EXPIRED | 同上；后台系统原因，非家长拒绝 |
| READY | 实际提供后家长确认 | FULFILLED | 记录兑现成人/时间/说明；不再扣账 |
| READY | 孩子/家长取消 | CANCELED | 原价退A、回库、释放原周额度 |
| 任何终态 | 再次相反操作 | 拒绝或返回原结果 | 不再产生账务 |

所有订单均须批准，包括家长代孩子发起。READY 无自动到期，家长通过站内待办持续看到承诺。孩子和家长可以取消未兑现订单；家长拒绝和取消必须写原因。FULFILLED 不提供取消或退款，额外补偿是新的手动表扬。

批准和到期同时发生，必须在锁内重新取服务端时间；`now >= approvalExpiresAt` 时只能到期释放，不能批准。取消与兑现竞争最多一个成功，第二个操作者看到最新状态。

价格/版本不符的新申请必须让用户重新确认，不静默按新价格预留。已批准订单不得在兑现时再校验新价、扣第二次积分或索要额外分。

## 8. 待办、历史与生命周期

### 8.1 待办和记录

家长首页三个固定队列：完成待审核、兑换待批准、奖励待兑现；可按孩子过滤并直接到详情处理。所有待办使用完整查询，不因首页最近30条而漏单。客户端从后台回来、下拉刷新、操作成功后刷新相关摘要。

孩子看到本人提交/退回/通过和兑换变化；默认站内呈现，无须订阅消息权限。未到达通知不影响审核、兑换和到期处理。

历史支持日期、孩子、类型和状态筛选，稳定游标分页；保存昵称/奖励/计划快照用于解释当时事实，允许当前名字作为旁注。自由文本和照片不进入普通服务器日志或跨孩子缓存。

### 8.2 归档前置

孩子归档：无 SUBMITTED/NEEDS_CHANGES，无 PENDING_APPROVAL/READY；否则列阻塞项并跳转处理。余额非0须确认保留只读账本，不能自动扣到0。归档撤销 DIRECT 与 DELEGATED 孩子会话；未来日常适用集合在查询时排除此孩子，历史事实不改写。

家庭归档：全部孩子满足待处理清空，负责人确认；撤销孩子会话，全家业务只读，可查看历史与办理隐私数据申请。最后一位成人不直接退出造成无主数据。

账号退出某家庭与微信账号注销不是一回事。负责人退出先转让给有效共同家长；移除家长只移除该家庭关系并吊销所派生的孩子会话，不能删除他曾经审核的账务事实。

### 8.3 隐私与数据处理

必须有实际可办的导出、删除与进度查询。负责人申请家庭全量数据；账号本人可申请个人数据，DIRECT 孩子账号通过自己的资料/隐私子页提出，不能导出全家。不能把 DELEGATED 的“本人”理解成源家长并泄露家长账号资料。

归档立即生效但不删除；删除按 [06-技术文档](06-技术文档.md) 的资格、处理状态、时限及备份策略执行，前端显示真实状态。图片清理、导出文件过期、删除在备份恢复后的重新清理都属于实施范围。

负责人注销个人账号前，必须对每个负责的家庭先转让负责人，或先归档并完成该家庭在线主数据删除。仅归档仍需保留有效负责人，个人删除申请保持待处理并给出下一步，不能让只读家庭无人管理。

## 10. 验收、依赖与实施顺序

需求验收映射：FR-01—07 对应身份/家庭组，FR-08—16 对应计划/积分组，FR-17—21 对应奖励/订单组，FR-22—26 对应历史/生命周期/网络/运维组；详细编号见 [07-验收与实施交接](07-验收与实施交接.md)。不得以旧测试通过替代新身份和预留账务测试。

建议实施顺序：身份/资料/媒体底座 → 家庭与孩子绑定 → 日常/挑战/提交审核 → 账本与奖励三步流程 → 历史/生命周期/数据处理 → 微信真机及并发/恢复验收。每步交付可运行切片，不要求等待所有视觉页面完成后再接真实接口。

上线需要实际的小程序主体与AppID、合法服务域名、生产密钥管理、私有图片存储与处理能力、真实备份配置及可执行的隐私支持渠道。技术栈可替换，状态语义、账号绑定隔离、强制资料、照片权限和积分一致性不能删减。
