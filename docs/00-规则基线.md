# 积乐圈家庭版：统一规则基线

更新：2026-09-20 · 状态：当前业务规则基线。

本目录定义积乐圈当前产品规则：以家庭和孩子档案为主体，支持孩子独立登录与家长代办。本文是各文档共用的业务契约；变更此处必须同步需求、交互、数据模型、接口与验收。具体说明见各分册。

## 1. 产品与身份

- 面向约 4—12 岁儿童家庭，由家长决定适合自己孩子的活动与奖励；年龄是设计假设，不是医学建议或准入限制。
- 核心单位是家庭 `Family`，微信账号 `User` 通过 `GuardianMembership` 获得家长权限；孩子 `ChildProfile` 是家庭内独立档案，可绑定自己的微信账号，也可由已登录家长代操作。所有实际进入小程序的使用者必须微信登录，不能匿名访问家庭业务。
- 用户确认的登录方式：孩子可用自己的微信登录，家长也可在自己的账号下代孩子操作。`ChildProfile.boundUserId` 可空；同一孩子同一时刻最多绑定一个 User，同一 User 在同一家庭不能同时是家长和孩子，也不能绑定多个孩子。跨家庭权限独立，不能凭“我是家长”的前端选择升级既有家庭权限。
- 家庭唯一负责人 OWNER 负责成人邀请、移除、负责人转让、家庭归档及导出/删除申请；共同家长 GUARDIAN 具有相同的日常业务管理权。成人无积分账户，只有孩子有账户。
- P0 支持一个成人加入多个家庭、一个家庭多个孩子；每个孩子仅属于一个家庭，不跨家庭转分。不设可公开加入的群。
- 同一 User 在不同家庭可有不同关系；切换只列本人已获授权的最少家庭/角色/孩子上下文。DIRECT 不能由上下文切换取得未经 PIN 验证的家长权限，也不能列出其他孩子。没有家庭关系的新账号可以发起建家或接受邀请，但不能因此改变已绑定家庭内角色。
- 家长可为孩子提交、直接记录已完成、审核、申请兑换与兑现，即使记录由同一位家长代办也合法；单家长家庭须独立完成所有操作。账务保留操作者和受益孩子。
- 孩子视角有两种会话来源：DIRECT（孩子自己微信账号绑定档案）与 DELEGATED（家长设备上的受限会话），均绑定 `familyId + childId`。DELEGATED 切换孩子、退出孩子模式、访问家长数据均须验证源家长 PIN 并换取新权限；DIRECT 只能退出自己的登录，不能输入某个 PIN 升为家长。不能仅靠隐藏按钮保护。家长进入 DELEGATED 后当前成人会话须被服务端降权/撤销，不能保留可调用的管理 token。
- 家长 PIN 为账户级 6 位数字，首次进入孩子模式前强制设置并保存一次性恢复码。已设 PIN 的账户重新微信登录也先进入 LOCKED 会话，验证 PIN 才获得家长权限；微信身份验证本身不能绕过或重置 PIN。恢复码重置后轮换恢复码并吊销全部旧会话。未设 PIN 的成人可先完成家庭配置，但不能进入孩子模式。恢复码丢失且忘记 PIN 时不提供仅凭静默登录的自助解锁。
- 所有 User 首次微信登录后必须先真实上传一张头像并填写昵称，接受隐私说明，服务端原子确认 `profileCompletedAt` 后才能访问家庭、完成提交、兑换等业务；上传失败、仅填昵称或默认占位图均不算完成。仅资料上传/保存、身份绑定前置流程所需的最少说明允许在 PROFILE_ONLY 会话下访问，家庭或孩子内容不得泄露。已完整用户再次登录无需重复上传；可在账号设置修改。此处“真实上传”指有成功验证的用户上传文件，不要求真人脸部或实名照片。
- 家长称呼可用“妈妈”等非实名。家长新建孩子档案时昵称必填，档案头像也须使用家长上传的图片；年龄段选填，不收集学校、精确生日、住址、定位。孩子自己登录时仍须完成其账号头像昵称，绑定确认可同步到家庭档案，已有历史不改写。

## 2. 页面与范围

- 家长四个主导航：`首页 / 计划 / 奖励 / 家庭`。首页汇总待审核、待批准、待兑现；计划统一管理日常和挑战；奖励统一管理奖励与订单；家庭承载孩子、家长、设置、历史及隐私。
- 孩子三个主导航：`今天 / 心愿 / 成长`。今天整合当日日常与进行中挑战，用类型标签区分，不要求先“领取”。心愿同时提供奖励列表、一个当前心愿目标和我的兑换；成长显示本人完成记录与积分账本。
- P0 是完整可用的首发闭环；P1 是非首发增强，不能在首发页面做无响应的假入口。无支付、充值、现金、广告、公开社交、排行榜、积分惩罚、自动识别运动、定位轨迹、系统级游戏控制。
- 头像上传、完成照片、孩子微信账号绑定均为 P0。奖励封面使用内置插画；奖励自定义封面、部分权益消费、持续计时、每周累计目标、批量审批均为 P1。

## 3. 计划、发生实例与完成

- `ActivityPlan` 分为 ROUTINE（日常：每天/选星期重复）与 CHALLENGE（一次挑战：明确起止时间）。共用计划、版本、发生实例模型；不得以客户端筛选替代服务端周期约束。
- P0 计量方式 CHECK（完成即提交）、COUNT（次/个）、DURATION（整分钟）、DISTANCE（整米），一次达标获得固定整数积分；不按超额完成线性加分。目标是家长设置的家庭约定，不内置普适运动强度建议。
- 每条计划明确适用孩子。日常每个适用日每个孩子唯一实例；挑战每个适用孩子全周期唯一实例。孩子无须预先领取，打开今天列表即可完成。P0 不把多次记录相加，提交的是本次实例的总完成量，未达标可保存草稿。
- 实例 `ActivityOccurrence` 保存日期/窗口、目标、积分快照、计划版本、适用孩子；首次合法物化时按有效历史版本取值，不以访问时间改变归属。查询、提交与定时任务都可幂等物化。统计基于完整适用集合，不以实际打开页面者作分母。
- 固定时区 Asia/Shanghai，日常窗口为当地日 `[00:00, 次日00:00)`；挑战为 `[startsAt, endsAt)`。UTC 存时间戳，业务日期另存 DATE，服务端时间为准。
- 日常创建/指派默认次日生效，可明确选择“今天开始”，此时今天从生效时刻起适用；已发布日常的编辑、移除适用孩子、暂停/恢复均次日生效，今日实例不改变。新加孩子不会追补其加入前任务。
- 挑战发布后目标、奖励、适用孩子与窗口冻结；只能修改展示性描述（不改完成要求）或停止。停止立即阻止尚未提交者的新提交；已提交可审核，NEEDS_CHANGES 可按已获补充期限继续补充。停止不撤销已得积分。重做用复制为新挑战。
- 允许发布已经开始但尚未结束的挑战；每个孩子实例的实际开放时刻是计划开始、实际发布/指派、孩子建档时间中的最晚者，不能给创建或指派前的完成事实补记积分。
- 实例持久状态：OPEN、SUBMITTED、NEEDS_CHANGES、APPROVED、EXEMPTED、REVOKED。未开始/逾期是时间派生展示状态，不把所有未完成记录定时改写。
- 孩子提交达标结果后进入 SUBMITTED；家长通过时一次到账。退回需原因，进入 NEEDS_CHANGES，允许在 `max(原截止时间, 本次退回时间+24小时)` 前补充；截止前提交的记录可在截止后审核。每次退回均重新计算补充期限并记录历史。
- 家长可对未提交或需补充的实例直接“记录完成”，在同一事务中确认结果和加分，标记代录；日常补记最多过去 7 个业务日，含今天共 8 个日期，挑战仅截止后 7×24 小时内补记。补记仅适用于真实存在的历史适用实例。
- 家长代录传实际 `completedAt`，须在原实例窗口内且不晚于当前时间，另记服务器 `recordedAt`。停止挑战后也可如实补记，但实际完成必须早于 `stoppedAt`，操作仍须早于原 `endsAt + 7×24小时`；标记“停止后补记”。不为停止后才完成的结果发挑战奖。
- 家长可将 OPEN / SUBMITTED / NEEDS_CHANGES 设为 EXEMPTED（今天休息/本次免做），原因必填，不发分且不计应完成数；P0 不恢复免做实例。
- 已通过不能编辑，纠错走原积分记录完整撤销：可用积分足够才能撤销一次；实例变 REVOKED，不得再次自动发奖。可另外使用有原因的手动表扬。禁止负余额与任意惩罚性扣分。
- 日常完成率 = APPROVED 数 /（完整适用实例数 − EXEMPTED 数），分母为零时展示“今天没有安排”；REVOKED 不计完成但仍入分母。挑战只按状态数量单列，不和日常混算百分比。

### 3.1 完成照片（P0）

- 孩子提交和家长代录都可附 0—3 张照片，不强制；文字说明仍可选。照片仅辅助家庭确认，不自动证明达标，不做运动识别。可拍照或从相册选择，取消选图不丢表单。
- 每张原始文件最多 10 MiB，仅 JPEG/PNG/WebP；服务端检查真实格式和像素总量（最多 4,000 万像素）、重编码去除 EXIF/GPS，完成照片最长边缩至 1600 px，头像裁为正方形并输出 512 px JPEG。原图校验后不长期保留。处理前不能生成可提交的 READY 媒体。
- 每张照片有上传中/处理中/可用/失败状态；所有被选照片均 READY 才可提交，失败可重试或移除后无图提交。不把上传成功当成活动提交成功；提交使用媒体 ID 和幂等键，不接受任意外站 URL。
- 媒体绑定上传者、家庭、孩子和实例用途；已提交照片不可替换，退回后新提交追加新版本，旧照片仍属旧提交历史。仅当前有权家长及对应孩子可以查看，私有存储配合鉴权后短时读取，缓存清理遵守作用域。
- 完成照片自首次正式提交起保留 180 天，退回后重复引用不延长；到期清理并在历史注明“照片已按保存期限清理”，文字/积分事实仍保留。未正式提交的完成照片（包括草稿引用）自上传起 24 小时清理，到期草稿显示需重新选择；提交前页面提示期限。当前账号/孩子档案正在使用的头像不适用上述清理期限。家庭删除和账号隐私请求的覆盖范围、备份期限详见技术文档。

## 4. 积分与心愿

- 正整数积分；一次活动奖励/手动表扬 1—1,000，奖励价格 1—100,000；新发分后总持有不得超过 1,000,000，这是新增奖励的准入上限。退款/释放预留不可因此失败，退款后可以暂时超过该值，此时暂停新发分。数据库使用非负 64 位整数，API 校验安全整数，不接受小数、负数或浮点积分。
- 账户有 `availablePoints`（可用）与 `heldPoints`（申请预留）；持有总额为两者之和。预留不算已花掉。所有变动均有不可改写流水、业务来源、操作人、结果余额与版本。
- 不过期、不借贷、不转账。历史完成奖励计“赚取”，预留/释放不计收入/支出，批准时才计兑换支出；撤销和退款独立列示。
- 一个孩子最多一个当前心愿，仅作目标收藏，不预留积分/库存。进度用可用积分/当前价格，上限 100%；下架时显示暂不可兑，保留名称，允许换目标。

## 5. 奖励与兑现

- 奖励类别 TIME（如游戏20分钟）、FOOD（如一份冰淇淋）、ITEM、EXPERIENCE；每一份权益描述明确，数量固定一份。时间奖励不控制手机，也不自动计时或拆分使用。
- 支持 FINITE / UNLIMITED 库存；发布后库存模式冻结。可限制每个孩子每自然周兑换次数（周一00:00开始）；可指定适用孩子。未来价格/说明变化不改已有订单快照。
- 所有兑换请求先由家长批准，包括家长代孩子发起的请求。状态：PENDING_APPROVAL → READY → FULFILLED；也可 PENDING_APPROVAL → REJECTED / CANCELED / EXPIRED，READY → CANCELED。
- 提交请求原子预留可用积分、占用一份有限库存及原申请周额度；批准时将预留积分正式扣除，不再扣库存；拒绝/申请取消/72小时未批准过期释放预留、库存和额度；批准后未兑现取消全额返还原价、恢复库存及原申请周额度。
- 每周额度统计该申请周的 PENDING_APPROVAL / READY / FULFILLED；不按批准/兑现日期重算。已取消/拒绝/过期不占额度；改限额仅影响新请求，已有订单保持。
- 72 小时截止使用服务器时间，`now >= approvalExpiresAt` 时不能批准。后台任务与请求前检查共同确保过期最终释放；延迟清理时前台标记处理中，不虚报可用积分。
- READY 不自动过期，代表家长已承诺，需要家长主动安排兑现。孩子和家长都可取消本孩子未兑现订单；家长拒绝/取消必须填写原因，孩子取消使用预设理由即可。
- 家长实际交付食物/物品、完成体验或已提供约定游戏时间后确认兑现。批准不是兑现，已兑现不可取消或退款；额外补偿通过有原因的手动表扬，无重复退款。
- 奖励下架/归档阻止新请求，不影响已有订单批准、兑现、取消；订单已确认快照不再次按新价计算。仅在新请求时核对 `expectedRewardVersion + expectedCostPoints`。

## 6. 生命周期与一致性

- 邀请仅成人使用：负责人生成一次成功入会有效、24小时有效、可撤销的随机令牌；受邀人登录确认申请，负责人审核后加入。邀请码不是孩子登录凭据。
- 批准加入时邀请码仍须未过期、未撤销且未成功使用；多个待申请仅第一笔成功批准占用令牌，其余标记邀请已失效。到期未批准须重新邀请；申请人可撤回待申请。
- 孩子绑定使用独立 `CHILD_BIND` 邀请，负责人针对已建孩子生成，24小时/单次成功/可撤销。孩子完成登录资料后申请，负责人核对账号头像昵称并确认绑定；受邀人不能改目标 childId。绑定已有账号不得直接覆盖，需负责人先解绑再发新邀请；解绑立即撤销 DIRECT 会话，保留孩子账本、历史和家长代操作能力。加入家长与绑定孩子的令牌不能互换用途。
- 移除/退出成人即时撤销其家庭访问及所派生孩子会话；负责人必须先转让才可退出。最后一名成人不能退出，只能走家庭归档流程。
- 孩子归档前处理其 SUBMITTED / NEEDS_CHANGES 完成记录与 PENDING_APPROVAL / READY 订单；有非零积分时明确确认保留只读账本，不能无提示清零。归档孩子不可继续操作；恢复档案为 P1。
- 家庭归档前所有孩子无待处理完成/订单，归档后全部只读并撤销孩子会话。数据导出、删除请求为 P0 设置项，实际处理路径和期限由技术文档定义，不能把归档等同于删除。
- 负责人删除个人账号前，须逐家庭转让负责人，或先完成相应家庭的在线主数据删除；仅将家庭归档不满足个人删除条件。不得留下没有有效负责人的只读家庭。
- 所有关键写操作由服务端身份、家庭与孩子作用域校验；服务端事务涵盖状态、积分/库存/额度、流水、审计和 outbox。采用乐观版本与幂等键，网络结果未明须查原操作，不能用新 key 重做。
- 默认通知仅站内待办；微信订阅消息为 P1，不能依赖通知到达保障主流程。小程序提醒无法保证准点后台运行。

## 7. 文档边界

上述为当前产品的实施决策，正式交付以 P0 验收通过为准。外部数据导入单独评估，不从群组或成人账户自动推断孩子与亲属关系。
