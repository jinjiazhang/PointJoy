# 积乐圈 · PointJoy：完整功能与开发规格

版本：1.0

整理日期：2026-09-18

依据：PointJoy 0.2.2 的前后端代码、数据模型及已确认的产品要求。

适用对象：产品、设计、前端、后端、测试，以及独立开发同类小程序的团队。

本文定义一个以群组为单位，通过日常、活动及人工奖励获得积分，再兑换虚拟权益或实物的微信小程序。阅读本文即可了解模块划分、页面结构、角色权限、核心流程、数据关系和验收要求。

**强制要求：用户登录后必须先更新头像和昵称，完成有效资料保存后才能使用业务功能。** 本文采用“每次登录检查、首次登录或资料未完善时强制更新”的规则；已经完成设置的用户再次登录无需重复更换照片或昵称。头像、昵称以后仍可在“我的”修改。

本文是开发规格，不代表所有要求已经上线。现有能力与新增要求的差异见第 15 节；尤其是强制完善资料，目前尚未在代码中实现。

## 1. 产品范围与基本约定

### 1.1 产品目标

- 一个微信用户可创建、加入多个群组，并随时切换当前群组。
- 每个群组独立管理成员、管理员、日常、活动、积分、奖励及兑换订单。
- 管理员发布内容，成员参与并提交完成说明，管理员审核通过后自动发放积分。
- 管理员可直接奖励或调整成员积分，成员可兑换虚拟权益或线下领取的实物。
- 所有涉及积分、库存、审核和权限的操作均可追溯。

### 1.2 核心约定

| 概念 | 定义 |
| --- | --- |
| 用户 | 全局账号，头像、昵称跨群共享 |
| 成员 | 用户在某个群组内的身份；同一用户在不同群可有不同角色 |
| 群主 | 一个群唯一的负责人，拥有管理权限并可任免管理员、转让群主 |
| 管理员 | 仅在所在群拥有业务管理权限 |
| 日常 | 每个成员每天最多参与一次，按北京时间自然日重置 |
| 活动 | 有明确开始、结束时间的限时项目，每个成员最多参与一次 |
| 积分 | 当前群内使用的整数余额，不跨群流通，不兑换现金 |
| 奖励 | 可以用积分兑换的虚拟权益或实物，均有库存 |
| 核销 | 管理员确认已经交付奖励，将待领取订单置为完成 |

当前范围不包含支付充值、现金提现、物流配送、聊天、排行榜、自动识别完成结果、低龄儿童专属流程、群组解散、成员退出/移除、积分跨群转账。不要把这些能力作为现有功能交付。

## 2. 页面结构与入口位置

底部固定五个主页签：**群组、日常、活动、奖励、我的**。日常和活动是独立主页签，不能合并为同一页面的类型切换。

| 页面 | 所有人可见内容 | 管理员/群主额外入口 |
| --- | --- | --- |
| 登录 | 品牌介绍、微信登录、错误重试 | 无 |
| 完善资料 | 选择头像、填写昵称、保存并继续 | 无；此页面为业务访问前置关卡 |
| 群组首页 | 当前群、群切换、本人积分、奖励推荐、近期积分流水 | 成员管理、日常审核、活动审核、兑换管理 |
| 日常 | 每日项目、参与/提交、当天状态、文字链接“日常记录” | 与普通成员一样参与，不放发布管理入口 |
| 活动 | 限时项目、时间标签、参与/提交、文字链接“参与记录” | 与普通成员一样参与，不放发布管理入口 |
| 奖励 | 上架奖励、类型筛选、详情、兑换 | 不放奖励编辑、库存管理入口 |
| 我的 | 个人资料、当前群身份、本人积分、我的兑换、积分明细 | 日常管理、活动管理、奖励管理；辅助入口可放操作记录 |
| 我的群组 | 已加入群组、身份、人数、积分，创建群、输入邀请码 | 无额外全局权限 |

管理页面归属必须清晰：

- “我的 → 日常管理”：发布日常、查看定义、停止参与。
- “我的 → 活动管理”：发布限时活动、查看定义、停止参与。
- “我的 → 奖励管理”：创建、编辑、上下架、库存调整。
- “群组首页 → 日常审核”：按日期和成员检查日常完成情况。
- “群组首页 → 活动审核”：查看限时活动完成情况。
- “群组首页 → 兑换管理”：确认交付或取消订单。
- “群组首页 → 成员管理”：入群审核、成员详情、积分操作、群主权限操作。

管理入口仅向当前群管理员及群主显示。移动端与宽屏端遵循相同业务归属。群资料设置、操作记录属于辅助管理功能，不应挤入成员参与页。

## 3. 登录、头像昵称与会话

### 3.1 微信登录

1. 用户点击微信登录，客户端取得临时登录凭据。
2. 后端向微信校验凭据，识别或创建账号；同一微信身份重复登录不得重复创建用户。
3. 后端签发业务会话，客户端保存凭证。
4. 进入资料完整性检查；检查通过之前不加载群组业务数据。
5. 资料完成后：没有群组则进入创建/加入引导；有一个群组则进入该群；有多个群组则优先恢复上次有效选择，否则让用户选择。
6. 登录失败显示原因与重试入口。会话失效后重新登录，不丢失尚待确认操作的关联信息。

### 3.2 强制完善头像和昵称（新增必做）

**进入条件：首次登录，或已有账号尚未完成有效头像和昵称设置。** 每次登录及恢复会话均检查服务器返回的完成状态。

完善页包括：头像预览、“选择头像”、昵称输入框、“保存并继续”。允许使用微信提供的头像选择能力及昵称输入能力，也允许用户选取自定义图片、填写昵称；不要求用户的内容与微信账号资料完全相同。

| 项目 | 必须满足的规则 |
| --- | --- |
| 头像 | 用户主动选择并成功上传到服务端，不能用颜色占位、文字头像或失效临时路径作为完成依据 |
| 昵称 | 去除首尾空格后 1～24 字；必须由用户填写或确认，自动生成的“伙伴xxxxxx”不能自动算完善 |
| 完成条件 | 头像与昵称均有效且保存成功；仅填写其中一项不能进入业务页面 |
| 跳过/关闭 | 不提供跳过；返回、重启、页面直达、分享链接均不能绕过 |
| 上传失败 | 保留已填昵称，允许重新选择或重试，继续停留在完善页 |
| 保存结果不明 | 使用原幂等请求重试或重新查询完成状态，不能假定保存成功 |
| 完成后 | 回到原目标页面；若目标已失效，则进入群组选择或首页 |
| 后续修改 | 在“我的”修改，头像或昵称不得被改为空；同步更新所有群内展示 |

推荐同时保存 `profileCompletedAt`，以服务端确认有效头像、昵称后设置。不能仅凭客户端布尔值、昵称是否符合某个前缀或头像 URL 是否存在来放行。

后端同样拦截未完善用户的群组、积分、日常、活动、奖励和兑换接口，返回 `PROFILE_INCOMPLETE`。仅允许登录、读取自己的资料、上传头像、保存资料、退出登录等必要接口。头像和昵称分步保存时，仅在两项都成功后标记完成；采用统一提交接口时应原子更新资料与完成标记。

头像文件要求：JPG/PNG/WebP、最大 2 MB；验证真实图片内容，限制像素数量，统一处理为 256×256 图片并保存在可通过 HTTPS 访问的长期地址。不要保存客户端临时文件路径。

### 3.3 会话与生产配置

业务会话与微信凭据分开管理，数据库保存会话令牌摘要和有效期；现有实现会话有效期为 24 小时。退出登录使当前会话失效。生产环境不开放演示账号登录；AppSecret、上传密钥、数据库密码仅保存在受控服务端环境。

## 4. 群组与权限

### 4.1 创建和切换群组

- 创建字段：群名称 2～30 字、简介 0～200 字、主题色。
- 创建者成为群主，同时建立群成员身份与余额为 0 的积分账户。
- 一个用户可创建/加入多个群，群列表展示名称、角色、人数和本人积分。
- 切换群后清空旧群页面数据，重新读取新群权限和业务信息；慢请求不能覆盖后来选择的群。
- 所有操作明确显示所属群，积分、奖励、审核、库存和订单不能串群。
- 有结果尚未确认的写操作时，先确认原操作结果，再切换群、账号或发起其他写操作。

### 4.2 邀请与入群

1. 管理员生成邀请码，可复制分享。
2. 当前约定有效期 7 天，最多用于创建 100 次入群申请；次数按创建申请计，拒绝不会返还次数。
3. 用户输入邀请码提交申请，查看自己的待处理/通过/拒绝结果。
4. 管理员在成员管理中通过或拒绝申请。
5. 通过时建立成员身份与独立积分账户；申请通过前不能访问群内内容。
6. 同一用户重复提交同群待审核申请返回原申请，不新增、不重复消耗次数；已是成员则提示已加入。
7. 无效、过期、撤销或名额耗尽的邀请码给出明确错误。

### 4.3 角色权限矩阵

“管理权限”均包括群主；普通管理员不能任免管理员或转让群主。

| 功能 | 普通成员 | 管理员 | 群主 |
| --- | --- | --- | --- |
| 查看当前群主页、日常、活动、上架奖励 | 是 | 是 | 是 |
| 参与并提交自己的日常/活动 | 是 | 是 | 是 |
| 查看本人积分、参与记录、兑换订单 | 是 | 是 | 是 |
| 使用本人积分兑换、取消本人待领取订单 | 是 | 是 | 是 |
| 查看全群成员及成员积分明细 | 否 | 是 | 是 |
| 生成邀请、审批入群、修改群资料 | 否 | 是 | 是 |
| 发布/停止日常和活动、管理奖励与库存 | 否 | 是 | 是 |
| 查看全群完成情况、审核提交 | 否 | 是，不能审核自己 | 是，不能审核自己 |
| 人工发分、调整和冲正 | 否 | 是，不能操作自己 | 是，不能操作自己 |
| 查看全群订单、取消待领取订单 | 否 | 是 | 是 |
| 核销订单 | 否 | 是，不能核销自己 | 是，不能核销自己 |
| 设置/撤销管理员、转让群主 | 否 | 否 | 是 |
| 查看群内操作记录 | 否 | 是 | 是 |

转让群主后：新负责人获得群主权限，原群主变为管理员；群、积分、订单及历史数据保留。角色来自服务端当前状态，每次请求重新核验，不能依赖前端缓存或隐藏按钮实现授权。

## 5. 群组首页与成员管理

### 5.1 首页展示

- 当前群和切换入口，用户昵称问候。
- 我的可用积分，提示“仅在本群使用”。
- “去兑换奖励”“积分明细”快捷入口。
- 推荐上架奖励与“全部奖励”。
- 近期积分流水：原因、时间、操作人、积分增减、变动后余额。
- 管理员专属四个按钮：成员管理、日常审核、活动审核、兑换管理。
- 没有奖励、流水或成员时给出空态说明和适用引导。

### 5.2 成员管理

- 查看待审核入群申请，执行通过/拒绝。
- 查看成员头像、昵称、角色、当前积分。
- 成员详情展示近期积分流水，可继续查询历史。
- 从成员列表或详情进入发积分，选定成员、操作类型、数值和原因。
- 群主可设置/撤销管理员、转让群主，操作前二次确认。
- 本人仍在成员列表中，但对自己的发分、冲正、角色转让目标等不允许操作。

## 6. 积分管理与流水

### 6.1 积分来源和去向

| 类型 | 方向 | 规则 |
| --- | --- | --- |
| 人工奖励 `GRANT` | 增加 | 管理员给其他成员，必须填写原因 |
| 日常/活动审核通过 | 增加 | 按参与时保存的奖励积分自动到账，关联参与记录 |
| 调整 `ADJUSTMENT` | 增加或减少 | 非零整数，必须填写原因 |
| 兑换 `REDEEM` | 减少 | 成功创建兑换订单时立即扣减 |
| 取消退款 `REFUND` | 增加 | 待领取订单取消后全额退还原扣积分 |
| 冲正 `REVERSAL` | 原数值的相反数 | 新增纠错流水，不删除或修改原流水 |

人工奖励单次 1～1,000,000；调整范围 -1,000,000～1,000,000 且不为 0；原因 1～200 字。余额不得为负，金额均为整数。总量设置上限（当前 2,000,000,000），还需预留待领取订单可退款空间，避免退款溢出。

### 6.2 冲正规则

管理员可冲正本群其他成员的奖励/调整流水，同一原流水最多一次。冲正扣分后不能产生负余额。兑换扣分和取消退款必须走订单流程，不允许直接冲正。

现有实现的日常/活动自动发分也记录为 `GRANT`，因此可被冲正。冲正只纠正积分，不把已审核参与记录恢复为待审核，不允许重新通过再发一次积分；页面应保留原审核及冲正痕迹。

### 6.3 一致性

余额更新与流水新增必须在同一数据库事务内完成，每条流水保存变动前因、增减数、变动后余额、操作者及业务关联。流水只追加不可覆盖，账户版本单调递增；并发奖励、兑换、取消都不能丢失更新。

“近期入账”如展示，必须注明统计范围，不能把最近 100 条流水的正数合计称为累计收入；退款、冲正是否纳入需按指标名称明确。

## 7. 日常模块

### 7.1 日常管理

入口：“我的 → 日常管理”。仅显示日常，不提供切换成限时活动的按钮。

发布字段：名称 1～60 字、完成要求 1～2,000 字、奖励积分 1～2,000,000,000 的整数。发布后立即可参与。

管理列表展示名称、要求、积分、状态；可停止参与。停止后不再允许新参与，但已有记录在自己的截止时间前仍可提交，待审核记录仍可审核。关闭不可恢复；需要重新开展时发布新的日常。

**当前范围中，日常“管理”包含发布和停止，不包含修改已发布定义。** 奖励积分及完成标准发布后固定，避免成员执行期间标准变化。若后续增加编辑，应另行定义版本与历史快照规则。

### 7.2 成员参与日常

1. 在“日常”主页签查看项目及本人当天状态。
2. 点击“参与日常”，为当天生成参与记录。
3. 完成实际事项后点击“提交完成”，填写 1～1,000 字完成说明。
4. 等待管理员审核；通过后自动得分，驳回后显示原因。
5. 在截止前可修改被驳回的说明并重新提交，复用同一条参与记录。

日常周期采用 **Asia/Shanghai（北京时间）00:00～次日 00:00**；左闭右开，到次日 00:00 即不能提交前一天记录。每个成员每个日常每天最多一条记录，不能靠刷新或重复点击再次参与。新一天生成新记录，不覆盖前一天记录。

### 7.3 日常记录

“日常记录”作为文字链接进入独立页面，不增加主页面子页签。按时间倒序展示本人历史参与日期、名称、状态、积分、完成说明、审核说明和截止时间；支持刷新及分页加载。

### 7.4 日常审核

入口：“群组首页 → 日常审核”，固定日常类型。

- 默认今天，可选历史日期，不选未来日期。
- 支持“按日常”“按成员”两种视角。
- 按日常：展开一个项目，看到所有适用成员的状态。
- 按成员：展开一个成员，看到该成员当日各日常的状态。
- 汇总显示已完成数/适用项数、待审核数；未参与也须明确展示，不能只列提交者。
- 状态包括未参与、进行中、待审核、需修改、已完成、已截止未提交、已截止未通过。
- 日期适用口径：成员在该日结束前加入；日常在该日结束前创建，且未在该日开始前关闭。停止日仍包含该项目。
- 展开待审核记录查看完整说明，选择通过并发积分或驳回修改。
- 通过说明可选，驳回原因必填（最多 200 字）。不能审核自己。
- 昨日已提交但未审核的记录可在之后处理；截止限制的是参与/提交，不限制管理员处理已提交记录。

## 8. 活动模块

### 8.1 活动管理

入口：“我的 → 活动管理”。字段同日常，另需开始和结束时间，以北京时间输入显示。结束时间必须晚于开始时间且晚于创建时刻；允许开始时间已到、结束时间尚未到的活动。

发布后状态按时间显示“未开始/进行中/已结束”，同时独立保存是否已停止参与。可以主动停止新参与；已有参与记录仍按原结束时间提交，已提交记录仍可审核。当前范围不修改已发布定义，不提供重新开启。

### 8.2 成员参与活动

- 独立“活动”主页签，醒目显示“限时活动”标签及完整起止时间。
- 仅在 `开始时间 ≤ 服务器当前时间 < 结束时间` 且未停止时允许参与。
- 每个成员每个活动终身最多一条参与记录，不按天重置。
- 提交说明、驳回修改、审核发分流程与日常一致。
- 达到结束时间不能新参与、提交或重新提交；已提交记录可继续被审核。
- 通过文字链接“参与记录”查看本人活动历史，不增加参与记录页签。

### 8.3 活动审核

入口：“群组首页 → 活动审核”，固定活动类型，不能混入日常记录。

支持按活动、按成员展开，显示完成数、待审核数和每条记录。活动适用成员为结束前入群的成员，已经存在参与记录的成员也应纳入；在活动结束后才加入且无参与记录的成员不标成“未完成”。其余审核规则与日常一致。

### 8.4 参与状态机（两类共用规则、独立存储）

| 原状态 | 操作/条件 | 新状态 | 积分变化 |
| --- | --- | --- | --- |
| 无记录 | 参与成功 | `CLAIMED` 进行中 | 无 |
| `CLAIMED` | 截止前提交说明 | `SUBMITTED` 待审核 | 无 |
| `SUBMITTED` | 管理员驳回 | `REJECTED` 需修改 | 无 |
| `REJECTED` | 截止前重新提交 | `SUBMITTED` | 无 |
| `SUBMITTED` | 管理员通过 | `APPROVED` 已完成 | 增加参与时的奖励积分快照 |
| `CLAIMED` / `REJECTED` | 到达截止时间 | 原状态保留，展示已截止 | 无 |

不允许直接从进行中审核通过；不允许重复提交待审核记录；已通过记录不再次审核。通过、积分入账、审核信息和流水关联必须一次事务提交。

## 9. 奖励商店与奖励管理

### 9.1 成员奖励商店

- 展示当前群已上架奖励，支持全部、虚拟权益、实物筛选。
- 卡片包括名称、封面、所需积分、可用库存、奖励类型。
- 详情包括描述、领取说明、当前余额、库存及兑换确认。
- 库存不足、积分不足、奖励下架时阻止兑换并显示原因。
- 一次兑换一份；管理员与群主也使用本人积分兑换。

### 9.2 奖励管理

入口：“我的 → 奖励管理”。

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，1～50 字 |
| 描述 | 0～2,000 字 |
| 类型 | 虚拟权益 `VIRTUAL` / 实物 `PHYSICAL` |
| 封面 | 当前从咖啡、图书、游戏、植物、礼物、电影等预设封面选择 |
| 兑换积分 | 必填，1～2,000,000,000 的整数 |
| 初始库存 | 0～1,000,000 的整数 |
| 领取说明 | 必填，1～500 字，说明联系对象和领取方法 |

- 新建后为草稿 `DRAFT`，需管理员上架为 `ACTIVE` 才可兑换。
- 上架后可下架为 `INACTIVE`，下架后可重新上架。
- 支持编辑名称、描述、兑换积分、领取说明；当前不编辑类型和预设封面。
- 库存独立调整：输入非零整数增减及原因，不能把可用库存调为负数。
- 奖励内容、上下架使用内容版本；库存调整使用库存版本，防止覆盖他人改动。
- 下架或修改不改变已有订单的成交价格及奖励快照，待领取订单仍可正常履约。
- 不直接删除有业务历史的奖励；用下架保留关联关系。

## 10. 兑换、取消与核销

### 10.1 兑换流程

成员查看奖励 → 确认积分和领取说明 → 提交兑换 → 校验版本/价格/库存/余额 → 原子扣积分与库存并创建待领取订单 → 展示订单详情。

客户端提交奖励 ID、看到的奖励版本、看到的积分价格；实际定价由服务端读取。价格或版本变动返回“奖励信息已更新”，要求重新查看确认，不能按新价格静默成交。

订单保存成交积分和奖励快照（名称、类型、封面、领取说明），后续编辑不能改写历史订单。库存减一和积分扣减有任何失败，整笔兑换回滚。

### 10.2 我的兑换

“我的”展示本人当前群订单，可查看详情、奖励、成交积分、兑换时间、状态和交付/取消说明。本人只能取消自己的待领取订单。虚拟权益由管理员确认实际兑现，实物由管理员线下交付；当前不收集收货地址、不自动发货。

### 10.3 兑换管理

首页的“兑换管理”供管理员查看全群订单，可按全部、待领取、已完成、已取消筛选。

- 核销：先实际交付，再填写交付备注并确认，订单变为已完成。
- 管理员不能核销自己的订单，需要另一位管理员/群主处理。
- 取消：本人或管理员填写取消原因，待领取订单全额退款并恢复一份库存。
- 已核销和已取消是终态，不允许再次取消、退款或核销。
- 同一订单相同结果的重复请求返回原结果，不产生第二次退款或扣库。

| 原状态 | 操作 | 新状态 | 积分/库存 |
| --- | --- | --- | --- |
| 无 | 兑换成功 | `PENDING` 待领取 | 扣积分、库存 -1 |
| `PENDING` | 核销 | `FULFILLED` 已完成 | 不再扣分扣库 |
| `PENDING` | 取消 | `CANCELED` 已取消 | 原积分全退、库存 +1 |

## 11. 操作记录与公共交互

### 11.1 操作记录

管理员可查本群操作时间、操作人、动作、目标、原因。覆盖入群决策、权限变更、群主转让、积分调整/冲正、日常/活动发布与关闭、参与/提交/审核、奖励编辑/上下架/库存、订单取消和核销。新增业务修改应补充相应审计，展示中文动作名称。

记录不能由普通成员读取，不能因删除界面内容而丢失。审计、积分流水、库存流水各自保留：审计解释“谁做了什么”，流水解释“数值怎么变了”。

### 11.2 公共体验

- 加载中、无数据、权限不足、失效、网络失败、处理中、结果未确认均有明确界面。
- 危险或影响余额的动作显示确认内容：转让群主、角色调整、冲正、停止参与、上下架、审核、取消、核销。
- 请求中禁止重复点击；写操作超时保留原请求，提供“重试确认”，不显示虚假的成功或失败结果。
- 刷新及返回页面后更新余额、库存、权限和业务状态。
- 长昵称、长标题、多行说明可换行或合理省略；按钮不覆盖内容。
- 适配小屏、大屏、微信状态栏/胶囊、底部安全区和输入键盘；滚动末尾不被导航栏挡住。
- 列表历史用分页或加载更多；统计必须基于完整数据，不能拿首页摘要截断列表算全量完成数。

## 12. 数据模型与存储要求

推荐关系型数据库。日常、活动及两类参与记录分别建表，不使用一个混合“任务表”加模糊周期字段承载全部业务。

| 实体/建议表名 | 关键字段与用途 | 唯一性/关联约束 |
| --- | --- | --- |
| 用户 `users` | id、微信身份标识、昵称、头像、profileCompletedAt、创建时间 | 微信身份标识唯一；资料完成字段新增 |
| 会话 `sessions` | userId、tokenHash、expiresAt | tokenHash 唯一 |
| 群 `groups` | 名称、简介、主题色、ownerMemberId、version | 一个有效群主，必须是本群成员 |
| 成员 `members` | groupId、userId、role、version、加入时间 | groupId + userId 唯一 |
| 积分账户 `point_accounts` | groupId、memberId、balance、version | 一个成员在该群一个账户 |
| 积分流水 `point_ledger` | delta、balanceAfter、accountVersion、type、reason、actor、orderId、reversalOfId | 账户版本唯一；原流水最多一次冲正；订单同类型流水唯一 |
| 日常定义 `daily_routines` | groupId、title、description、points、status、creator、createdAt、closedAt | 主键唯一，关联当前群 |
| 活动定义 `events` | 日常同类基础字段，startsAt、endsAt | endsAt > startsAt |
| 日常参与 `daily_entries` | routineId、memberId、occurrenceDate、awardPoints、status、submission、expiresAt、审核信息、ledgerId、version | routineId + memberId + occurrenceDate 唯一 |
| 活动参与 `event_entries` | eventId、memberId、awardPoints、status、submission、expiresAt、审核信息、ledgerId、version | eventId + memberId 唯一 |
| 奖励 `rewards` | groupId、名称、描述、类型、封面、积分价、库存、领取说明、status、version、stockVersion | 库存非负 |
| 库存流水 `stock_ledger` | rewardId、delta、stockAfter、stockVersion、type、actor、orderId、reason | 奖励库存版本唯一；订单同类型流水唯一 |
| 兑换订单 `redemptions` | memberId、rewardId、costPoints、rewardSnapshot、status、履约/取消信息、version | 始终关联同群成员与奖励 |
| 邀请 `invitations` | groupId、codeHash、expiresAt、maxUses、uses、revokedAt | codeHash 唯一 |
| 入群申请 `join_applications` | groupId、applicantUserId、invitationId、status、决策人/时间/原因 | 同一用户同群最多一条待处理申请 |
| 幂等记录 `idempotency_records` | userId、scope、key、请求摘要、原响应 | userId + scope + key 唯一 |
| 审计 `audit_logs` | groupId、actorMemberId、action、targetId、reason、时间 | 按群和时间索引 |

所有业务实体以不可猜测的 ID 标识，查询和修改必须同时检查群关联，不能只查资源 ID。用外键/组合约束及事务保证关联正确；角色、状态、余额、库存需有数据库约束或等价的严格服务端校验。

时间戳以带时区形式保存，业务日单独保存日期。日常当天的结束时间在参与时确定；活动参与保存原活动结束时间。参与时保存 `awardPoints`，审核必须读此快照，不能临时读取被修改后的定义积分。

为群+时间、成员+时间、待审核状态建立索引。大列表使用稳定排序（createdAt、id）和游标，头像文件独立于数据库保存并纳入备份。

## 13. 接口契约

以下路径以 `/api/v1` 为前缀；`{gid}` 为群 ID，`{id}` 为相应实体 ID。接口名称可在新项目调整，但权限、字段和状态语义必须保留。

### 13.1 公共协议

- JSON 请求/响应，HTTPS；鉴权使用 `Authorization: Bearer <token>`。
- 业务写操作携带 `Idempotency-Key`（UUID）；同用户、同接口、同 key、同内容返回原结果，同 key 不同内容拒绝。
- 成功：`{"data":{...},"requestId":"..."}`。
- 失败：`{"error":{"code":"...","message":"..."},"requestId":"..."}`。
- 分页：`limit` 默认 30、最多 100，`cursor` 可选；返回 `items/hasMore/nextCursor`。
- 涉及可变信息时提交 `expectedVersion` 或对应业务版本；冲突返回错误，刷新确认后用新请求提交。
- 必须校验字段类型、长度、枚举、空格、积分整数及关联资源，不接受客户端传来的角色作为授权依据。

### 13.3 关键请求示例

```jsonc
// 发布日常
{"title":"阅读30分钟","description":"完成阅读并提交一段心得","points":10}

// 发布活动：带时区时间
{"title":"周末运动","description":"完成一次运动并提交说明","points":30,"startsAt":"2026-09-19T08:00:00+08:00","endsAt":"2026-09-20T22:00:00+08:00"}

// 提交完成
{"submission":"阅读了30分钟，记录了三个要点。","expectedVersion":1}

// 审核通过
{"decision":"APPROVE","reason":"完成情况符合要求","expectedVersion":2}

// 兑换奖励
{"rewardId":"<奖励UUID>","expectedRewardVersion":3,"expectedCostPoints":50}
```

示例说明使用注释分隔，实际 HTTP JSON 不包含注释。

### 13.4 错误与恢复

| 错误 | 用户处理 |
| --- | --- |
| UNAUTHENTICATED | 重新登录，再检查资料完成状态 |
| PROFILE_INCOMPLETE（新增） | 转到强制完善资料页 |
| FORBIDDEN / SELF_OPERATION_FORBIDDEN | 告知无权限或不能处理自己的记录 |
| RESOURCE_NOT_FOUND | 刷新或返回；不泄露其他群资源信息 |
| VALIDATION_ERROR / INVALID_AVATAR | 在字段附近显示错误，保留输入 |
| VERSION_CONFLICT / REWARD_CHANGED | 刷新最新信息，再确认提交 |
| INSUFFICIENT_POINTS / OUT_OF_STOCK | 提示积分或库存不足 |
| ALREADY_CLAIMED / ACTIVITY_EXPIRED / ACTIVITY_UNAVAILABLE | 刷新参与状态、时间和按钮 |
| INVALID_STATE / ALREADY_REVERSED | 提示已经处理或当前状态不允许 |
| IDEMPOTENCY_KEY_REUSED | 停止错误重试，检查请求是否被修改 |
| RATE_LIMITED | 延迟重试，不连续刷请求 |
| 超时、断网或 5xx | 保留原请求内容与 key，提示“结果尚未确认”，用原请求重试 |

## 14. 核心验收清单

以下场景必须通过，不能只验证页面能打开。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 新微信用户首次登录 | 强制进入资料页，不能创建群、参与或兑换 |
| A02 | 只保存头像或只保存昵称 | 不放行业务接口；自动默认昵称不算完成 |
| A03 | 资料页返回、重启、直接打开业务页 | 仍进入资料页，服务端也拒绝业务访问 |
| A04 | 有效头像昵称均保存成功 | 放行；下次登录检查通过后无需重复更换 |
| A05 | 上传失败/昵称保存超时 | 保留输入，结果未明可安全重试，不误标完成 |
| G01 | 同用户在 A 群为管理员、B 群为成员 | 切换后权限和余额完全独立 |
| G02 | 使用其他群的成员、奖励、参与、订单 ID | 查询或写入被拒绝 |
| G03 | 重复提交入群申请或重复批准 | 不重复创建成员/账户，不重复消耗邀请次数 |
| G04 | 群主转让、旧管理员被降权 | 新权限即时生效，旧页面请求仍重新鉴权 |
| P01 | 管理员发分、扣分、冲正 | 余额与流水一致；负余额禁止；冲正仅一次 |
| P02 | 给自己发分、审核自己、核销自己 | 全部被后端拒绝 |
| D01 | 日常当天重复参与 | 仅一条记录；次日可生成另一条 |
| D02 | 北京时间 23:59 提交、次日 00:00 提交旧记录 | 前者允许，后者拒绝 |
| D03 | 日常审核按成员/按项目切换 | 同一日期数据一致，未参与者也可见 |
| D04 | 新成员或新日常查看过去日期 | 不把尚未适用的内容算作未完成 |
| E01 | 活动未开始、到开始时间、到结束时间 | 仅有效时间窗口允许参与和提交 |
| E02 | 活动跨天重复参与 | 仍最多一条；不按天重置 |
| R01 | 进行中直接审核 | 拒绝；只有待审核可处理 |
| R02 | 驳回后截止前/截止后重新提交 | 前者允许、后者拒绝；使用同一条记录 |

| R04 | 截止后审核已提交记录 | 可以通过发分或驳回，不能补交过期记录 |
| R05 | 停止日常/活动 | 禁止新参与，原参与在原截止时间内仍可提交 |
| W01 | 奖励草稿、上架、下架、重新上架 | 成员商店仅显示上架奖励 |
| W02 | 两人争抢最后一份奖励 | 仅一个成功，库存和余额不为负 |

## 15. 当前实现差异与开发交付边界

### 15.1 已有主要能力

微信登录与主动修改资料、多群创建/加入/切换、群角色、成员积分操作、日常和活动独立存储及主页签、按成员/项目审核、奖励管理、兑换与核销、业务流水、幂等重试与并发保护。0.2.2 已将三类内容管理入口移到“我的”，审核和兑换入口放到首页。

### 15.2 本文新增必须实现的要求

1. **强制头像昵称完善**：现有登录仍可使用自动昵称和占位头像直接进入业务。需要新增完成状态、阻断页面、后端守卫、失败恢复与对应测试。
2. 登录提示文案改为“登录后请先设置头像和昵称”，不能再提示资料可稍后自行填写。
3. 资料完成后再读取和展示业务数据；已有不完整账号同样进入完善流程。

### 15.3 复刻时需要补齐的交付项

- 现有部分页面只展示摘要或近期记录；若交付“全部记录”，必须接完整分页，不能沿用截断数据作为全量。
- 当前移动端操作记录入口不完整，宽屏已有入口；应在移动端“我的”提供辅助文字入口，并把新日常/活动审计动作映射成中文。
- 群资料修改等业务需逐项核查审计覆盖，补齐遗漏。
- 日常和活动目前不支持编辑已发布内容；不要仅因入口名叫“管理”而承诺存在编辑接口。奖励已支持有限字段编辑。
- 本文不要求重置数据。上线强制资料要求时给现有用户增加未完成状态并引导补充，保留群、积分、订单与参与历史。

### 15.4 同类项目交付物

交付至少包含：微信小程序工程、后端工程、数据库迁移脚本、环境变量示例、头像存储方案、部署说明、接口说明、管理员/成员操作说明、验收测试及测试结果。生产系统应有 HTTPS、日志请求号、数据库与头像备份及可执行恢复方案。

可沿用现有技术组合：uni-app + Vue 3 + TypeScript + Pinia；NestJS + TypeScript；PostgreSQL + Prisma；Nginx 反向代理。技术可替换，但权限隔离、状态转换、时间口径、积分/库存事务与幂等规则不能省略。
