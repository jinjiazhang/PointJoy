# 备份恢复与权限保护重放

此流程必须在 API、worker 和外部入口停止后执行。数据库或媒体恢复成功不代表可以直接开服：旧备份可能包含已经撤销的家长关系、孩子绑定、旧 PIN、已删除的文本、照片及导出文件。

## 恢复前准备

1. 记录事故编号、执行人、数据库备份时间、媒体备份时间及目标恢复点，保留当前损坏实例供取证。确认使用应用与数据库备份相匹配的迁移版本。所有密码、加密密钥通过受控环境文件或 Secret 注入，不粘贴到命令参数和工单。
2. 停止 `pointjoy-api` 和 `pointjoy-worker`，将公网入口置维护状态。数据库恢复操作使用独立运维身份，先在隔离环境验证。不要将应用运行账户临时提升为超级用户。
3. 获取独立保管的最新安全保护目录。它包含每个事件的 AES-GCM `.enc` 文件以及 HMAC 签名的 `manifest.json`，必须与 `SECURITY_JOURNAL_KEY` 配套。**不能用数据库或媒体旧备份覆盖安全保护目录。** 日志目录和密钥的独立副本是否存在、是否完整、是否最新，必须由日志保管人确认。
4. 验证备份清单和校验值，解密数据库及私有文件备份到仅运维可读目录。数据库使用 `pg_restore --exit-on-error` 恢复，媒体和导出恢复至配置的独立目录。不要在日志目录内解压普通业务备份。
5. 使用迁移部署命令确保存在 `004-recovery.sql` 的恢复记录和物理清理队列表。迁移校验失败时停止，不能改旧 migration 的校验和强行通过。

## 重放命令与放行条件

配置与 API 相同的 `DATABASE_URL`、`MEDIA_DIR`、`EXPORT_DIR`、`SECURITY_JOURNAL_DIR`、`SECURITY_JOURNAL_KEY`。运行：

```sh
npm run recovery -- --operator OPERATOR_NAME --journal-custody-confirmed
```

`--journal-custody-confirmed` 表示保管人已经确认独立日志未回滚，不是跳过完整性校验。未提供该标志、缺少清单、清单签名错误、事件缺失、文件摘要不符、解密失败、发现未封存事件，都会拒绝恢复。工具不会重新生成缺失的清单。它还要求已恢复数据库中的所有安全事件都存在于清单中。

恢复程序依次执行：

- 撤销全部恢复出来的会话，清空旧认证响应、二次验证、图片读取及导出读取凭据；取消尚未确认的 PIN 设置，撤销恢复出来的邀请码与未决加入/绑定申请。
- 按日志时间读取事件，并结合单调增长的身份版本处理撤权和解绑；删除已撤销的 `FamilyPrincipal`。不会根据最少安全字段自动创建新的 User、家长关系或孩子绑定。资料缺失或负责人发生变化而无法完整复原的家庭进入 `DELETING`，所有业务访问被禁止，并列入报告等待核验。
- PIN 日志只有启用标记、账号安全版本及凭据版本，不含 PIN 哈希、恢复码哈希或秘密。若日志中的凭据版本比备份新，或备份尚未启用 PIN，清除旧 PIN/恢复码以及待确认凭据，设置 `recovery_blocked=true`，同时保留 `enabled_at`。微信登录仍得到 `LOCKED`，旧 PIN 和旧恢复码均不能解锁。此情形需要人工独立核验，不能仅凭重新微信登录重置。
- 根据独立日志中已授权的删除事件，重新删除家庭在线数据，或清理账号身份、本人孩子敏感文本、照片引用和私有文件。对其他操作者保存的幂等响应去除相关个人资料，同时保留必要的幂等键，避免旧请求再次发分。
- 作废恢复出的全部导出包并删除物理副本，扫描私有目录中失去有效数据库引用的文件。物理删除先记入 `recovery_file_cleanup`，删除成功并同步目录后标记完成；进程中断后重跑同命令继续处理。存在无法删除、非法路径或权限错误的文件时不放行。
- 运行领域对账，记录 `recovery_runs` 和审计结果。日志与报告只列事件编号、主体编号、计数、状态和错误码，不记录秘密、照片内容或敏感文本。

命令输出 JSON 报告：

| 字段 | 含义 |
| --- | --- |
| `status` | `READY` / `HOLD` / `FAILED` |
| `safeToStart` | 仅为 `true` 时允许进入后续开服验证 |
| `heldFamilies` | 需要独立核验的家庭及原因 |
| `blockedPinUsers` | 旧凭据已失效、仍待核验的账号 |
| `pendingFiles` | 尚未完成的物理清理数，必须为 0 |
| `deletedFamilies` / `deletedAccounts` | 本次重新执行的删除范围 |
| `reconciliationStatus` | 必须为 `PASS` |
| `issues` | 阻断原因代码 |

仅 `READY` 且 `safeToStart=true` 返回退出码 0；`HOLD` 或 `FAILED` 返回 1。尚有人工核验、清理失败或对账异常时保持维护状态。完成独立核验后应按变更记录修复关系/凭据、生成新的合法保护事件、再次封存日志并重跑；本 CLI 不提供“强制放行”或恢复旧凭据的选项。不可仅把家庭 `DELETING` 改回 `ACTIVE`，也不可只关闭对账事件。

## 开服前与恢复后验证

确认所有旧 token、旧恢复码、已撤销成员以及解绑孩子的直登均失效；允许保留的关系经新微信登录和合法 PIN 验证后能使用。确认已删除资料无法通过媒体、导出、幂等回放和后台查询重新取得。重跑 `npm run reconcile`，核对关键家庭余额、预留、库存和订单，再启动 worker 处理合法的到期任务。最后逐步恢复 API 和公网入口，记录恢复耗时、实际恢复点及测试结果。

## 可重复隔离演练

准备 Node 24、PostgreSQL 16，以及可执行的 `pg_dump`、`pg_restore`：

```sh
createdb pointjoy_recovery_test
npm run test:recovery
```

`RECOVERY_TEST_DATABASE_URL` 可指定测试主机和角色，但数据库名必须精确为 `pointjoy_recovery_test`。测试会重建该库并真实执行 dump/restore；不能指向任何生产、开发或其他测试数据库。必要时用 `PG_DUMP_BIN` / `PG_RESTORE_BIN` 指定兼容的客户端工具路径。测试生成的微信账号、图片内容、PIN 和密钥均为隔离夹具，不连接真实微信账号。

演练覆盖旧备份之后的新撤权、解绑、PIN 变更、账号删除、家庭删除与未知新绑定；验证恢复前后领域对账、旧凭据拒绝、敏感文件物理清理、重复重放、缺失备份后事件和未确认保管状态时关闭访问。功能测试通过不能替代生产 RPO/RTO 实测。

## 已知边界

签名清单可以发现单文件丢失或篡改，无法单独证明整个目录没有被换成一份更旧但签名有效的快照；这一点依赖独立保管确认。当前实现为独立于数据库备份的文件日志，未配置跨机房存储凭据，不能声称已经具备跨机房灾备。整机磁盘损失且无独立日志副本时必须保持关闭访问，不能从普通旧备份推断缺失撤权或删除事实。人工 PIN 恢复仍需有充分的独立核验材料，本工具不降低该标准。
