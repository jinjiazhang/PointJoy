# 领域不变量集成测试与账务冻结恢复

本目录使用真实 PostgreSQL、会话校验、事务、行锁、幂等记录和 HTTP 路由。测试通过显式数据库夹具建立已完成资料的账号，微信网络登录和图片转码由 `tests/integration/` 的完整流程覆盖。

## 运行

使用 Node 24 和 PostgreSQL 16，先创建一次专用数据库：

```sh
createdb pointjoy_domain_test
npm run test:domain
```

可设置 `DOMAIN_TEST_DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/pointjoy_domain_test`。测试脚本只接受这个精确数据库名，每次删除并重建该库的 `public` schema，再运行全部 migration；不会复用生产库、开发库或根集成测试库。凭据通过本地环境或 CI Secret 注入，禁止提交真实密码。服务账号需有该专用数据库的 schema 管理权限。

覆盖重复审核与重复操作、最后库存并发预留、每周额度、批准与退款、到期时释放、撤销不可变账本、日常次日生效及未来预览、历史版本/指派/归档边界、七日补记、停止挑战后的不同处理、兑现取消并发、超准入上限的原价退款以及异常冻结和显式恢复。测试中的过去发布时间是确定的数据库夹具；不修改主机时钟，也不在生产 API 暴露时间覆写。

## 对账异常的处理

`npm run reconcile` 以一致快照检查余额、预留、账本逐笔余额和版本、活动奖励与撤销、订单扣退、库存、周额度、归档阻塞及计划版本重叠。存在异常时返回失败退出码，并创建 `reconcile_incidents.status=OPEN`。

- 指定 `child_id` 的事件冻结该孩子的全部积分写入；未指定孩子的家庭事件冻结整个家庭；未指定家庭的事件冻结全局。冻结期间不能批准、释放、退款或继续发分，避免在不可信余额上扩大差异。查询和已有幂等结果仍可读取。未冻结的其他孩子继续正常使用。
- 到期任务跳过被冻结的账户，并保留待处理订单供修复后继续处理；不伪造 `EXPIRED` 成功状态。接口提供 `ACCOUNT_FROZEN` 和账户 `frozen` 标记。任务不会用修改账本来消除差异。
- 运维先保存事件、对应导出和最新备份；定位错误版本，在变更记录中说明根因、修复 SQL/代码及执行人。只有来源账本、订单、审核等事实可信时，才可在事务和家庭锁保护下重建派生余额、库存或额度。来源事实存在矛盾时保持冻结，人工查明；不可删除事件、覆盖原始账本或用任意加分“抵消”错误。
- 修复后运行 `npm run reconcile`。`PASS` 不自动解除旧冻结。使用下面的命令显式申请恢复，工具在家庭排他锁内重新检查该作用域的所有不变量；仍有问题时拒绝。成功关闭事件并写入含执行人、原因与事件 ID 的审计记录。

```sh
npm run reconcile:resolve -- \
  --family FAMILY_UUID \
  --child CHILD_UUID \
  --operator OPERATOR_NAME \
  --reason '修复记录编号及验证说明'
```

省略 `--child` 会检查并解除该家庭全部已修复事件；指定孩子不能解除家庭级事件。命令使用 API 相同的 `DATABASE_URL` 配置，没有公开 HTTP 入口。仅运维角色可通过受控终端执行。全局事件须先确认全局根因并走经审批的数据库运维处理，不提供跳过检查的通用开关。恢复后重跑到期任务和对账，验证待释放订单、账户余额及审计记录。生产发布前还需按运行手册完成备份恢复、监控报警和目标负载验收，不能将此功能测试结果当作性能或恢复指标实测。
